## 任务一实现 Append

先写出 current child、已打开/已访问状态和 EOF 的含义。open 建立本轮状态，不提前打开所有孩子。next 只推进当前孩子；当前 EOF 后关闭或推进到下一孩子，保留行重复次数。发生 open/next/rescan 失败时清理已访问资源，保留原始错误，并使输出不能被误消费。

| 输入或事件 | 应观察的行为 |
| --- | --- |
| A=[1,1,2]，B=[]，C=[2,3] | 输出 [1,1,2,2,3]；空孩子不产生行 |
| 只请求第一个结果 | 不提前打开后续孩子 |
| 第二个孩子 open 失败 | 已打开孩子得到清理，第三个不打开 |
| 输出部分行后 rescan | 按接口重绕已访问孩子，从头重新给出结果 |

## 任务二实现 Unique

为完整行定义结构相等与哈希，包含列数、类型、NULL 和值表示。保持第一次出现的行并惰性读取；next 找到一个新行后就返回，不为方便而一次吃完所有输入。已见键需要稳定所有权。rescan 清空集合，再按生命周期重置孩子；失败后按接口限制后续动作。

| 输入 | 预期 |
| --- | --- |
| 两列 (NULL::INT,1)，(NULL::INT,1) | 只保留第一行 |
| 两列 (1,2)，(1,3) | 两行都保留，不能只按第一列去重 |
| FLOAT -0.0 与 +0.0 | 按本题位表示规则区分，不套用 SQL = |
| 零列行输入 3 行 | Unique 后 1 行；与空输入的 0 行区分 |
| 哈希碰撞的两条不同完整行 | 仍保留两行，哈希值不等于身份 |

规划侧还要为 SELECT DISTINCT / UNION DISTINCT 包装节点，复制完整输出描述符，并保留显式零列 schema。执行侧测试通过不能代替这两个规划侧用例。相关语义属于该项目的给定契约，不推及所有数据库。
