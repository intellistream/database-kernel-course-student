# L0  环境准备与源码阅读

课内 2 学时。

目标是建立可重复的开发与验收流程，读懂一条查询经过的模块。本实验从起始框架开始。学生版的大量算法区域故意挖空，明确的“未实现”失败与工具链错误要分开记录。

## 准备材料与环境

使用 04_Ferrum实验基础 中清理后的 Ferrum-cpp-student.tar.gz，在 Linux 或 WSL2 的本机文件系统解压。源码构建和数据库文件使用本机磁盘目录。工具合同为 C++23、GNU g++ 13–15、CMake 3.22 以上、Ninja 和 Python 3.10 以上；dev.sh 提供 Debian 13/GCC 14 的 Docker 环境。先安装并启动 Docker。

```text
mkdir -p ~/db-kernel-2027
cd ~/db-kernel-2027
# 将学生源码包复制到本目录后执行
tar -xzf Ferrum-cpp-student.tar.gz
cd Ferrum-cpp-student
mkdir -p course-results/L0
export LABS_JOBS=2
./dev.sh list --stage 06
./dev.sh scaffold --report course-results/L0/scaffold.json
```

运行器默认构建并执行给定原语冒烟，不替学生补算法。Docker 镜像下载、编译器版本不符、缺少头文件和算法待实现是不同错误。首次运行可能较慢；提交首个根因及其上下文，不用最后一行“构建失败”代替诊断。

## 建立代码身份

```text
git init
git add .
git commit -m "Record supplied student baseline"
git rev-parse HEAD
git status --short
./dev.sh exec g++ --version
./dev.sh exec cmake --version
./dev.sh exec python3 --version
```

以上 Git 命令在新解压目录执行。若 Git 尚未配置作者身份，使用自己的课程身份配置后再提交。发放包使用独立的本地 Git 历史；报告记录源码包 SHA256 和本地提交号。

## 源码阅读步骤

先读 README.md、docs/course/conventions.md 和 labs/README.md。沿 libs/engine 的 Database/Session、libs/planner 与 libs/execution 阅读声明和调用。打开 labs/manifest.json，找出 S06.Q02 的路径、区域和测试名，再定位 LAB 标记。每个学生只负责被分配题号的区域，共享文件不意味着整文件都可以改写。

```text
rg -n 'LAB-S06\.Q02:.*-BEGIN' libs
./dev.sh unit S06.Q02 --report course-results/L0/append-initial.json
./dev.sh exec python3 -m unittest discover -s labs/tests -v
```

Append 初始算法桩失败是预期结果。运行器自身测试检查调度与报告逻辑。若单题返回注册或环境错误，按环境、注册和算法三类定位。

## 验收与答辩

验收检查环境记录能否复现、错误分类是否有依据、调用路径是否能定位到真实文件。答辩解释 pin 与页锁的区别、移动后对象的使用边界，以及 plan 命令生成的题集与依赖。记录表中保留“通过、失败、未执行、阻塞”四种状态。
