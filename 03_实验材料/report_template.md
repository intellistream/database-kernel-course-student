# 数据库内核实验报告

## 实验报告填写顺序

先写完成范围与结论，再给出环境、实现和证据。报告不必复述教材，重点解释自己的决策及其后果。

| 字段 | 需要填写的内容 |
| --- | --- |
| 身份 | 姓名/学号、实验号、题号、源码包哈希、本地提交与未提交差异 |
| 合同 | 输入、输出、状态不变量、允许修改的区域 |
| 实现 | 核心状态、所有权、同步或发布点、失败处理 |
| 验证 | 用例编号、最小输入、预期、实测、命令、日志文件 |
| 问题 | 一个真实失败、定位过程、修复与回归 |
| 后续工作 | 剩余任务、依赖与下一步验证 |
| 参考 | 资料、参考代码与 AI 辅助范围、独立完成部分 |

## 结果登记样例

```text
实验号: L3
题号: S06.Q02
状态: 通过 / 失败 / 未执行 / 阻塞（选择实际状态）
实际用例数: 由报告读取
命令: 原样粘贴
预期: 输入 A=[1,1], B=[2]，输出 [1,1,2]
实测: 填写运行结果
证据: JSON 报告路径与完整日志
解释: 状态转移与资源清理为何满足合同
```

## 个人答辩的检查点

能在真实文件中定位自己实现的区域；能在不运行前预测一个新输入；能解释错误码与资源状态；能区分局部测试与整库证据。教师可在已有用例上改变一个边界，如空输入、重复值、失败位置或事务交错，要求现场推演和小幅修改。
