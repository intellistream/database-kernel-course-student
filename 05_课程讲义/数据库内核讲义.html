第1讲 数据库内核与一次查询的执行

建议课内学时 2

数据库内核接收查询，把逻辑请求转化为页与记录的访问，并在并发和故障条件下维持约定的结果。本课程以 Ferrum-cpp-student 为实现主线。学习的基本单位是一段能说明输入、状态变化、输出和失败边界的算法，而不是一份能编译的源码。

从结果反推模块职责

考虑查询“成绩大于 90 分的学生编号”。解析器识别语法结构，绑定器把表名、列名和类型解析为确定对象，规划器选择扫描与过滤等节点，执行器拉取记录并计算谓词。访问方法把记录定位到页，缓冲池管理页在内存中的驻留；事务层决定读者能看到哪个版本。目录为这些模块提供表、列、索引及统计信息。

应用看到的是逻辑行。页布局、索引结构和缓冲策略可以改变，而 SQL 所表达的结果应保持一致。这是物理数据独立性在内核中的具体体现。新增索引后结果相同、读页数减少，是本课程反复使用的一种正确性与性能对照。

状态与资源一起阅读

C++ 的 unique_ptr 表达独占所有权，移动会转移资源；span 和视图通常借用别人的存储。页守卫释放后仍保存裸指针，即使地址暂时未变，也已越过有效期。PinGuard 防止帧被替换，页读写守卫保护内容访问，二者解决的问题不同。

Result/Status 把失败作为接口结果。阅读函数时先列出对外发布点：页表何时新增映射，输出行何时交给上层，事务状态何时变为提交。发布前失败应清理候选资源；发布后失败则需要与已有状态一致的处理。每个失败出口分别检查资源和状态。

第2讲 关系模型与多重集语义

建议课内学时 2

关系模型用属性、元组和完整性约束描述数据。关系代数通常按集合讨论，而 SQL 查询经常保留重复行。实现执行器时，是否去重必须由具体算子和语句决定，哈希结构应保留该算子要求的重复次数。

从代数运算到算子

选择保留满足条件的行，投影生成所需列，连接组合满足条件的两侧行。数据库可把这些运算组织成树：父节点向子节点请求输入，再产生自己的输出。一条逻辑连接可以用嵌套循环、哈希或归并执行；结果语义相同，代价与所需前提不同。

输入与运算结果实现含义
A=[1,1,2]，B=[1,3]；UNION ALL[1,1,2,1,3]保留各输入的重复次数
同一输入；UNION DISTINCT{1,2,3}去重；无 ORDER BY 不承诺输出顺序
R 的键 1 有两行，S 的键 1 有三行；等值连接键 1 产生 6 个行对连接结果是组合，不是任取一对

空输入与零列行

没有任何输入行与有一行但没有列是两种不同状态。前者基数为 0，后者基数为 1。执行器使用独立的 EOF 状态，以保留零列行。类似地，SUM 的空输入规则与 GROUP BY 没有任何分组的情况不同，需要在聚合章节分别处理。

约束如何进入实现

主键约束要求行可被唯一标识，唯一约束约束键的重复，外键把跨表引用变成持续成立的条件。约束从声明进入执行后，内核要在插入、更新、删除和并发冲突后保持它。一次失败更新如果已经修改堆记录，却没有恢复索引项，会破坏逻辑表与访问路径的一致性。

算例与练习

R(a,b)={(1,x),(1,y),(2,z)}，S(a,c)={(1,u),(1,v)}。等值连接 R.a=S.a 得到 (1,x,u)、(1,x,v)、(1,y,u)、(1,y,v)。投影 a 的 SQL 多重集结果含四个 1；加 DISTINCT 后才是一行 1。请用两层循环推导这四个结果，解释只保存每个键一行的哈希结构为什么不正确。

源码题目：S06.Q02 Append 流式串接；S06.Q03 全行 Unique；S07.Q02 嵌套循环连接；S07.Q03 Hash Join

课后给出一个反例，说明把 UNION ALL 改为 UNION 会改变上层 COUNT(*)。再解释：索引遍历顺序稳定，是否意味着不带 ORDER BY 的查询可以依赖该顺序？

第3讲 SQL 类型 NULL 与查询求值

建议课内学时 6

本讲用三次课建立 SQL 语义基础：先讨论定义与更新，再讨论过滤、连接与排序，最后讨论聚合、子查询与集合运算。每次先手算小数据结果，再追踪绑定和执行过程。沿绑定、表达式和输出路径检查类型支持。

绑定先于求值

解析只回答语句是否具有某种语法结构。绑定还要解决列来自哪个关系、是否存在歧义、参数和表达式是什么类型。对于 SELECT id FROM a JOIN b ON a.id=b.id，如果两表都有 id，未限定的投影列应报告歧义。类型转换遵循统一规则。

三值逻辑

SQL 谓词可能为 TRUE、FALSE 或 UNKNOWN。与 NULL 的普通比较通常得到 UNKNOWN；WHERE 和 HAVING 只保留 TRUE。NULL = NULL 不得到 TRUE，而 IS NULL 用于检查缺失值。布尔短路与类型检查、错误传播之间还需要遵守具体接口，用三值类型保存 UNKNOWN。

ABA AND BA OR B
TRUEUNKNOWNUNKNOWNTRUE
FALSEUNKNOWNFALSEUNKNOWN
UNKNOWNUNKNOWNUNKNOWNUNKNOWN

聚合的计算范围

WHERE 在分组前过滤输入，GROUP BY 按键形成分组，聚合计算每组状态，HAVING 再筛选聚合结果。COUNT(*) 统计行数，COUNT(x) 统计 x 非 NULL 的行数。SUM(x) 忽略 NULL；若没有非 NULL 输入，结果是 NULL。全局聚合的空输入仍形成一个结果行，带 GROUP BY 的空输入没有分组，输出零行。

sales(dept, amount):
(A,10), (A,10), (A,NULL), (B,20), (B,20)

SELECT dept, COUNT(*), COUNT(amount), SUM(amount)
FROM sales GROUP BY dept ORDER BY dept;
-- A,3,2,20
-- B,2,2,40

三种比较规则

SQL 等号、结构相等和索引排序各有比较规则。Ferrum 的全行 Unique 按类型化表示比较，并按题目约定区分 FLOAT 的位表示，包括正负零；这是 Ferrum Unique 的比较约定。哈希相等需要与结构相等一致；比较列值时还要保留类型化 NULL。

排序 子查询与更新

ORDER BY 决定结果顺序，LIMIT/OFFSET 决定截取范围；排序键相同而没有进一步键时，按允许的并列顺序校验结果。EXISTS 只关心是否存在符合条件的行，相关子查询则需要在每次外层参数变化后重新绑定或重扫。DML 除了修改数据，还要协调约束、索引、事务和失败回滚。

第4讲 安全性 完整性与错误传播

建议课内学时 2

安全性回答谁能对哪些对象执行什么操作，完整性回答允许什么数据状态存在。二者都依赖可解释的边界：身份、对象和操作应明确，约束失败后留下的数据库状态也应明确。课程保留这些基础知识，并把重点落在错误如何穿过内核模块。

权限检查与执行权限

概念上，用户通过角色获得权限，权限绑定到对象和操作。最小权限意味着一个查询执行路径只获得它需要的能力。教材中的授权与回收用于理解模型；对应 SQL 的实现入口见目录与语法模块。

语句原子性与资源清理

向有唯一索引的表插入一行，至少涉及记录空间、堆修改、索引维护和事务记录。如果索引发现冲突，语句应返回失败，并按约定保留一个一致的状态。RAII 负责资源清理，事务机制负责撤销已发布的数据变更。

失败点应观察的事实常见遗漏
输入校验没有发布记录或索引项分配后忘记归还候选资源
唯一性检查表与索引保持一致表写入成功后直接返回错误
子算子 next上层不消费旧输出失败时保留上次输出指针
事务提交同步成功确认与持久状态一致write 返回后立即回复 COMMIT

故障注入方法

故障注入把失败放到可控的位置，例如让第 2 次读页返回 I/O 错误，让一个子算子的 open 失败。测试不仅检查错误码，还检查已打开资源是否只关闭一次、未访问分支是否保持未打开、输出槽是否被清空。注入点选在真实的可失败接口。

课堂讨论与练习

假设批量插入三行，第 2 行发生唯一冲突。整条语句回滚还是部分成功，由语句的原子性约定决定。给出两种合同下各自应保留的数据、错误结果和事务状态，再在 Ferrum 指导中查找当前路径的选择。

第5讲 函数依赖与数据库设计

建议课内学时 2

数据库内核训练仍需要理解数据设计。函数依赖来自业务语义，说明某组属性能够唯一确定另一组属性。索引选择与范式分解解决不同问题：索引改变访问方式，分解改变逻辑关系及其约束组织。

闭包 候选键与范式

求属性集 X 的闭包时，从 X 出发，反复加入所有左侧已包含在闭包中的依赖右侧，直到不再变化。若闭包包含全部属性，X 是超键；只有去掉任何属性都不再是超键时，才是候选键。讨论范式前先求候选键，再判断主属性。

R(student, course, teacher, office, grade)
依赖：
(student, course) -> grade
course -> teacher
teacher -> office

{student, course}+
= {student, course, grade, teacher, office}

在上述依赖下，(student,course) 是候选键。教师办公室重复出现在多条选课记录中，更新办公室容易漏改。可分解为 Enrollment(student,course,grade)、CourseTeacher(course,teacher)、TeacherOffice(teacher,office)。每个给定依赖都可在一张表内检查。

无损连接与依赖保持

无损连接要求分解后重新连接不会引入原关系没有的组合。二元分解中，共有属性能函数决定其中一个分量，是判断无损的重要条件。依赖保持则要求不做跨表连接也能通过各分量依赖检查原约束；两项性质分别证明。

本例先按 teacher -> office 分出 TeacherOffice，共有属性 teacher 决定该分量；再按 course -> teacher 分出 CourseTeacher，共有属性 course 决定该分量，因此可逐步说明无损。真实业务中若一门课允许多个教师，course -> teacher 就不成立，以上设计也必须重新分析。

设计如何影响内核工作量

分解减少冗余，却可能增加连接；反规范化可能减少读取，却增加更新维护。同时观察 SQL 条数、结果正确性、读写页数、维护索引的数量和事务冲突。课程中的 TPC-C 由给定数据模式定义，评测保持完整的数据关系和业务约束。

练习

给出 R(A,B,C)，依赖 A->B、B->C。求 A 的闭包，并讨论分为 (A,B)、(B,C) 的无损性与依赖保持。再尝试分为 (A,C)、(B,C)，构造一个连接后出现额外行的实例。阅读原课件第 6、7 章，并把一个函数依赖转化为具体数据反例检查。

第6讲 页 记录与缓冲池

建议课内学时 4

磁盘按页组织数据，内存中的帧承载驻留页。页号标识持久对象，帧号标识缓存位置。堆记录通过页号和槽号定位；变长记录移动时，可通过槽目录保持定位接口稳定。

一次 fetch 的状态变化

命中页表时增加 pin 计数，并按接口获取内容访问保护。未命中时，先寻找空闲或可替换帧；若候选帧脏，必须处理写回与错误，才能安全发布新页映射。并发 fetch 同一页需要协调“正在调入”的状态，否则会得到同页的两个不一致副本。取得候选帧后，还需按同步协议确认替换资格。

CLOCK 与脏页

CLOCK 给候选帧维护访问位并循环扫描。访问位提供近似的近期使用信息，pin 则是资格约束。pin>0 的帧保留驻留资格。unpin(page,false) 保留已有脏位；合并修改时，脏状态至少保留“旧脏或本次修改”的含义。并发回写还需区分写回批次与其后的新修改。

操作必须成立的状态理由
pin A、pin B 后请求 CA、B 均不可淘汰资源不足需明确报告
修改 A，再 unpin AA 可成为候选但仍为脏释放使用权不等于写回
淘汰 A，写回失败不发布 C 的成功映射保留 A 的最新副本
写回期间 A 又被修改新修改仍被跟踪旧批次完成不覆盖新脏状态

堆页的空间约束

槽目录保存记录位置和状态，页内空闲区用于存放记录字节。插入前既要检查记录空间，也要检查新增槽目录的开销。删除标记、物理回收和旧版本回收可能发生在不同时间，字节复用遵循版本回收条件。空闲空间映射只是候选信息，真正插入前仍需检查页面当前状态。

算例与源码阅读

缓冲池 2 帧，依次固定 A、B，请求 C；预期报告无可替换帧。释放修改过的 A 后再请求 C，应先安全写回 A。随后重新读取 A，内容应一致。再令磁盘写入失败，检查返回码、页表、脏位、pin 和旧页内容。

源码题目：S01.Q01 页文件读写与分配；S01.Q02 CLOCK 替换；S01.Q04 缓冲池调入与并发替换；S01.Q05 脏页回写与批次跟踪；S01.Q07 堆页槽位与空间组织

练习：画出“占用中、可淘汰、正在写回、正在调入”的状态转换，标出需要同步的位置。分别说明 pin 与页锁保护的状态。

第7讲 B+树与唯一索引

建议课内学时 2

B+树用内部节点缩小范围，用叶节点保存有序键与记录定位信息。高扇出降低访问层数，叶间连接支持范围扫描。本讲重点是将纸面分裂转成一致的页修改，并理解索引键与事务版本之间的关系。

下降与边界定位

查找时依据分隔键选择子页。lower_bound(k) 找到第一个不小于 k 的位置，upper_bound(k) 找到第一个大于 k 的位置。闭区间、开区间和半开区间对应不同边界组合；若停止条件差一个等号，就会丢行或多读边界行。

设叶容量为 3，叶中已有 [3,7,9]，插入 12 后按示例策略分为 [3,7] 和 [9,12]，向父节点传播分隔键 9。若原叶是根，还要建立新根并发布根页信息。此例只是推演分裂的状态变化，不规定 Ferrum 的真实容量或分裂比例。

复合键与唯一性

复合键通常逐列比较；(1,20) 小于 (2,1)，因为第一列已决定顺序。有符号整数、浮点、字符与 NULL 的排序应遵循类型契约，直接 memcmp 原始存储字节通常不等价。索引记录指向某个版本后，唯一性检查还需要分类该版本是已提交、待决、死亡还是需要等待重查。

遇到另一事务的待决键，等待后必须重新检查。等待前释放会阻碍对方推进的页守卫。索引和堆更新需要协调：修改唯一键发生冲突时，旧记录和旧索引映射要保持约定的一致状态。

算例与练习

叶链为 [3,7] -> [9,12,20]，范围 [7,20) 应输出 7、9、12。测试分别改变下界为 8、上界为 12，并加入不存在的边界和跨叶情况。分裂后分别检查父指针、叶链和范围终止。

第8讲 执行器 聚合与连接

建议课内学时 4

执行器把逻辑计划变成可推进的状态机。open 建立本轮状态，next 返回一行或 EOF，rescan 开始重新扫描，close 释放资源。某些节点流式处理，某些节点必须先积累输入；这决定了首行延迟、内存占用与失败清理的方式。

Append 与 Unique

Append 按子节点顺序串接行流。当前子节点 EOF 只意味着切换下一个子节点，全部子节点结束才是整个 Append 的 EOF。惰性打开使尚未访问的分支不占资源，也避免提前触发它们的错误。重扫时需要恢复已访问状态，并按实际打开状态处理各个孩子。

Unique 保存已见行集合，逐行读取直到发现新行。哈希只帮助定位桶，哈希值相同仍须进行结构相等比较。键应拥有稳定的行值；若只保存子算子复用的输出槽指针，后续覆盖会使集合内容变化。重扫必须清空已见集合，并按接口重置子节点。

输入 A: (1),(1),(2)
输入 B: (2),(3)
Append 输出: (1),(1),(2),(2),(3)
Unique(Append) 输出: (1),(2),(3)
说明：这是算子的稳定首现顺序；SQL 的最终顺序仍由 ORDER BY 约束。

聚合状态与连接状态

聚合维护每组的累加器。AVG 可用和与计数推导，但需要遵守类型、溢出及浮点规则；每个聚合的 DISTINCT 维护独立的去重状态。Hash Join 为一个键保存所有匹配行，探测到该键后输出所有组合。Nested Loop Join 则为每个外侧行重扫内侧，容易暴露重扫和参数生命周期错误。

策略必要条件或状态主要代价
嵌套循环外侧当前位置、内侧重扫朴素形式比较约 N×M 次
哈希连接等值键、哈希表及同键行集合构建内存与碰撞处理
归并连接两侧按连接键有序排序及重复键组的组合枚举

让 Append 的第二个孩子在 open 时失败，检查第一个孩子已清理、第三个孩子没有被打开。让 Unique 在输出一行后 rescan，检查旧集合不影响第二轮。逐行写出两侧重复键分别为 2 行和 3 行时的六个连接结果。

第9讲 查询优化与代价验证

建议课内学时 2

优化器选择语义等价而预计代价较低的计划。每项改写都需要两种依据：语义上保持结果，物理上满足算子的前提。代价估计错误通常影响速度；语义判断决定结果正确性。

谓词下推与索引范围

对内连接，某些只依赖单侧列的过滤可以提前执行，以减少中间行。外连接的 NULL 扩展会改变过滤含义，下推需要额外证明。把比较谓词转为索引范围时，还要保留类型转换、NULL、浮点及边界开闭规则；没有推导出来的条件仍由残余过滤验证。

有序性与 TopN

索引按 (a,b) 排序，不意味着扫描结果天然按 b 全局有序。如果 a 已限制为单值，b 的有序性才可能满足要求。ORDER BY + LIMIT 可用有界 TopN 降低内存，但 OFFSET=m、LIMIT=k 时通常要考虑前 m+k 个候选，保留范围覆盖这 m+k 个候选。并列键需要保持与查询规定一致的比较规则。

输入分数：70,90,80,100,90
ORDER BY score DESC OFFSET 1 LIMIT 2
完整排序：100,90,90,80,70
输出：90,90
有界候选至少覆盖前 3 个位置。

统计估计与观测

行数、不同值数、分布和相关性影响选择率估计。若十万行中 90% 都是同一个键，均匀分布假设会低估热门键的结果规模。ANALYZE 负责统计维护，但估计与实际仍可能不同。比较计划时记录估计行数、实际行数、读页数和执行时间，先确认输出多重集一致。

实验条件应固定的内容需要观察的量
扫描与索引对照数据、查询和事务快照输出、读页数、时间
排序与 TopN 对照排序键、边界与输入规模输出、峰值状态量、比较次数
连接顺序对照选择率、连接语义各中间结果行数、构建代价

第10讲 事务 锁与多版本并发控制

建议课内学时 6

事务把多个操作组织成满足原子性、隔离性和持久性的单位。一致性还依赖应用约束与正确的事务逻辑。本讲依次讨论冲突调度与锁、MVCC 快照、SI 与可串行化的差别；用同一组并发历史连接这三部分。

锁与等待图

共享锁允许兼容读者并存，排他锁与冲突访问互斥。两阶段锁通过限制加锁与解锁阶段约束调度；严格持锁策略进一步约束写锁释放。锁是事务级逻辑协调，闩锁通常保护短期内存结构。持有页闩锁等待事务锁，可能使完成方无法推进。

若 T1 持有 A 并等待 B，T2 持有 B 并等待 A，等待图形成 T1->T2->T1。检测到环后选择牺牲者并中止，随后还要释放资源、移除等待边和唤醒正确的等待者。发现环只是死锁处理的第一步。

快照与可见性

MVCC 保存多个版本，让读者按快照选择可见版本。假设教学快照用上界 xmax 和活跃事务集合描述：创建事务在快照取得前已提交、且不在当时活跃集合中，才可能对该快照可见。旧快照的可见性还取决于取得快照时的事务状态。删除或更新标记还需进行对应判定；自己的修改结合命令 ID 处理。

创建者状态读者取得快照时的事实通常的判定方向
已中止任何快照其新版本不作为可见结果
现在已提交当时仍活跃或在快照之后旧快照仍不见该新版本
此前已提交不在当时活跃集合还需检查删除或更新标记
当前事务自己同一事务不同命令按 command ID 与接口语义处理

RC SI 与写偏斜

RC 通常按语句取得读快照，SI 在事务内保持读快照并处理写写冲突。两事务分别更新不同行时，可能没有写写冲突，却共同破坏跨行约束。可串行化需要排除这类不可对应任何串行顺序的历史；SSI 通过读写冲突及裁决机制检测危险情形，根据冲突图结构和提交状态作出裁决。

值班约束是 A+B>=1。初始 A=B=1，T1 和 T2 都读到总数 2；T1 写 A=0，T2 写 B=0。SI 可能允许二者提交，最终总数为 0。若二者都写 A，便是同一目标上的写冲突，应作为独立的写写冲突测试。

第11讲 WAL 检查点与崩溃恢复

建议课内学时 4

持久性要求已经成功确认的事务在规定故障后仍可恢复。WAL 的关键是先后顺序：相关日志达到持久边界后，脏页才可写入稳定存储；提交成功确认也需要对应提交日志满足耐久条件。write 将数据交给操作系统，稳定化操作建立日志耐久边界。

位置与发布

WAL 分配位置、已写入位置、已同步位置分别描述不同进度。页 LSN 表示页面应用过的日志边界，不是当前 WAL 的耐久位置。多个事务可通过组提交共享同步，但每个成功 ACK 仍必须被相应耐久进度覆盖。

重做与事务可见性

物理 redo 恢复页结构；事务状态恢复决定哪些版本对 SQL 可见。Ferrum 重放中止事务的必要物理日志。B+树分裂或空间布局可能已被后续操作依赖。它的版本最终是否可见，由事务状态和 MVCC 再决定。教材的 undo/redo 分类提供恢复设计的比较框架。

若页面 LSN 已覆盖一条 delta 记录，重复重做应跳过；若尚未覆盖，则在候选页上应用并验证后发布。完整页镜像 FPI 或 WILL_INIT 可为缺页、坏页提供特定恢复路径，普通 delta 依赖有效的基页。具体读模式和边界以恢复端口为准。

教学简化示例
页初始 pageLSN=100，记录 endLSN=120
第 1 次：应用记录，发布新页，pageLSN=120
第 2 次：该记录已被覆盖，页字节不再改变
若候选页校验失败：保留原页，不发布半页结果

检查点与日志尾

检查点减少恢复扫描范围，但其控制信息只能在所依赖状态可靠后发布。停止接纳新工作、排空活动工作、刷日志与页、发布 control 是不同动作。日志尾可能是合法的未完成记录，也可能是中间损坏；把任意校验失败都当作可以截断的尾部，会掩盖数据损坏。

故障验证

崩溃实验采用强制终止进程的方式。测试应记录客户端真正收到成功 ACK 的事务集合，随后强制终止专用测试进程并重启，检查这些事务可恢复。ACK 未被观察到的事务可能已提交，其提交状态需要进一步核对。

第12讲 系统集成 性能评测与综合复习

建议课内学时 4

单题通过说明一个局部合同成立，完整数据库还需要模块正确接线。集成时按照环境、单元算法、真实 Database/Session、协议、恢复、性能逐层定位，避免把所有问题都归结为数据库跑得慢。

协议是可执行合同

收到的 grader 使用 rmdb_wire。功能查询使用 EXEC_STREAM，排名事务涉及 PREPARE_SET 和带类型的 EXEC_BATCH。一条消息可能跨越多次 recv；服务端必须正确处理分片、结束帧、错误与类型。Ferrum 服务使用 Wire 客户端。

正确性之后才比较性能

先验证输出多重集、约束、事务和恢复，再测量完成相同工作所需的时间。计时区间应区分数据加载、预热和正式窗口；失败重试也要计入所定义的观察范围。仅使用最快的一次结果容易把缓存或偶然波动误认为改进，课程对照使用固定条件下的多次结果与中位数。

本地教学观察意义不等价于
单元用例通过指定边界在该夹具下成立整库 SQL 正确
结果与参考一致该输入的语义一致全部输入均正确
已确认事务重启后存在该故障历史的恢复证据任意故障均安全
小数据耗时下降该条件下的性能变化决赛排名提升
