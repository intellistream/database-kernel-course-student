# 夹具与验收边界

[题目总览](README.md) · [练习流程](getting-started.md)

夹具为一道题提供确定的输入和可观察的依赖行为，让测试聚焦于该题的真实算法。`F-ROWS` 等名称是题库中的**契约标识**，不是一组已经全部实现的同名 C++ 类。

目前仅 [Append](questions/S06.Q02.md) 和 [Unique](questions/S06.Q03.md) 的独立用例完成注册与隔离验证。其他 81 题的测试配套仍待补齐。逐题指南列出的原有测试文件可用来理解场景，但其中可能调用其他尚未实现的算法。

## 各类夹具应该提供什么

| 标识 | 提供的输入或事实 | 仍由本题计算的内容 |
|---|---|---|
| F-IO | 临时文件、固定字节、短读写和同步失败事件 | 页分配、文件扩展及发布决策 |
| F-FRAME | 帧身份、固定状态、访问和竞争事件 | 替换器的候选顺序与选择 |
| F-BUFFER | 页镜像、指定候选、I/O 和 durable-LSN 回应 | 缓存映射、调入、替换与回写 |
| F-HEAP | 页、槽位、元组和已给定的事务事实 | 页空间选择、扫描推进、版本裁决 |
| F-TREE | 节点镜像、键、路径事实和访问事件 | 键比较、树下降、分裂或唯一性 |
| F-AST | SQL 文本或直接构造的 Source / Bound / Plan 描述，按被测层选择 | 解析适配、绑定、重写与规划 |
| F-ROWS | 按顺序返回的有限行及指定调用处的错误 | 过滤、排序、去重、聚合或连接 |
| F-CATALOG | 不可变模式、目录事实、ID 初态和发布事件 | 名称决策、DDL、代数推进与统计 |
| F-MUTATION | 记录操作、输入值和 RID，返回预定结果 | 目标映射、RID 去重、变更协调与索引维护 |
| F-TXN | XID/CLOG 事实、快照请求、完成回应和线程屏障 | 分配、可见性、锁授予和提交发布 |
| F-GRAPH | 事务、锁目标、边及确定的事件交错 | 环、危险结构和受害者判断 |
| F-WAL | 固定记录或字节以及 append/flush/publish 事件 | 组帧、日志生成选择、排队与检查点 |
| F-RECOVERY | 恢复前页、control 初态、类型化记录和故障 | redo、事务收尾与启动决策 |

表格说明职责，不承诺所有题目已经具备可直接调用的隔离端口。当前注册情况以 [manifest](../../labs/manifest.json) 为准。

## 已有的有限行流示例

[FixedRowsState](../../libs/execution/tests/fixed_rows_state.hpp) 继承给定的 `PlanState`，保存预先给出的行，记录生命周期调用，并在指定调用次数返回预定错误。它不求值表达式，也不执行去重或排序。

阅读它时可以分别观察：

1. 输入行在测试开始前已经确定，`next` 只推进有限脚本。
2. 调用记录能检查尚未访问的分支有没有被提前打开。
3. 故障位置由测试输入决定，可重现打开、推进或重扫失败。
4. 被测的 `AppendState` / `UniqueState` 仍使用正常产品类和本题实现。

实际用例见 [Append 测试](../../libs/execution/tests/append_lab_test.cpp)、[Unique 执行测试](../../libs/execution/tests/unique_lab_test.cpp) 和 [Unique 计划测试](../../libs/planner/tests/unique_lab_test.cpp)。

## 如何判断测试边界是否合理

以“输入一组页，测试范围扫描”为例，页端口可以按给定请求返回固定页，但不能提前筛出最终结果行。以“输入冲突边，测试死锁”为例，可以固定线程事件，不能由夹具预先选好受害者。

检查一个测试时，先指出被测函数，再追踪它调用的依赖。测试实际比较的应是算法输出、状态和事件，而不是函数有没有被调用过、有没有遇到桩，或进程有没有正常退出。

如果准备输入必须先运行另一个未实现题目，说明该测试尚未隔离。需要由课程维护者提供输入构造或受控端口，不应把补做其他题列为这道题的隐含要求。

## 单题测试和数据库组合测试

单题可以直接构造 AST、页镜像、快照或行流。数据库组合用例则通过真实 `Database/Session`、真实学生组件和正常 I/O 验证 SQL 与持久化行为；有限行流等夹具不替代其数据库内部算法。

| 记录的结果 | 含义 |
|---|---|
| 本题具名用例全部执行并通过 | 本次单题验收通过 |
| 仅构建成功或给定原语通过 | 底座检查通过 |
| 缺少测试注册 | 配套验收尚不可用 |
| 未执行、零匹配、跳过、崩溃 | 不构成本题通过证据 |
| 数据库组合尚缺能力或验证 | 不宣称组合可运行 |

新增独立用例需要登记构建目录内的二进制相对路径和精确 GoogleTest 名称。已有的 `existing_test_sources` 字段不等于注册。格式与运行命令见 [运行器说明](../../labs/README.md)，当前结果见 [验证记录](../../labs/verification.json)。
