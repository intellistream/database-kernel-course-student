# 从选题到完成一次练习

[返回题目总览](README.md)

先选一道题，读懂它的输入、输出和失败条件，再进入源码。阶段编号组织知识，不要求你按顺序写完前面的题。每题指南中的“延伸阅读”是知识关联。

## 1. 选择练习范围

在 [83 题索引](../../problem.md) 中按主题选题。第一次接触这套框架，可以从 [Append](questions/S06.Q02.md) 或 [Unique](questions/S06.Q03.md) 开始：它们已有独立测试，可以直接观察输入、输出和算子调用记录。

其他题的算法区间也已准备好，但独立测试注册或隔离验证仍待补齐。这是课程配套的待办，不要求你先实现未选题来填补依赖。

| 你想做的事 | 入口 |
|---|---|
| 理解一道题并动手 | 对应的 `Sxx.Qyy.md` 指南 |
| 了解同一主题的题目关系 | [阶段目录](README.md) |
| 确认类型、所有权和错误约定 | [共用约定](conventions.md) |
| 区分测试输入与待实现算法 | [夹具与验收边界](fixtures.md) |
| 查找固定的页、日志字节布局 | [格式速查](formats.md) |
| 查看完整命令和报告语义 | [运行器说明](../../labs/README.md) |

## 2. 建立可编译的起点

已有 Docker 时，在仓库根目录运行 `./dev.sh`。它使用 Debian slim 和 GCC 14，自动构建镜像并完成框架检查；后面的 `python3 labs/run.py ...` 可写成 `./dev.sh ...`。环境内容、缓存和可选分析工具见 [Docker 说明](../../docker/README.md)。

本机构建需要 Linux、受支持的 GCC/g++ 13–15、CMake 3.22 以上、Ninja、Python 3.10 以上和 `flock`。仓库内置第三方依赖源码。预设继承环境中的编译器选择；例如本机可指定 `CXX=g++-15`，容器已设置 `CXX=g++-14`。Clang 22 仅在显式开启格式化和静态分析时需要。

本机构建时，在**仓库根目录**执行：

```sh
CXX=g++-15 python3 labs/run.py scaffold
python3 labs/run.py list --stage 06
```

`scaffold` 会配置并编译默认目标，包括公共和私有头文件检查，然后执行登记的给定原语测试。它不执行所有数据库功能测试。初始版本的 27 个原语用例通过，只说明底座可用。

默认构建目录为 `build/gcc-release`。需要限制并行度时，可在命令前设置 `LABS_JOBS=8`。已有 CMake 缓存会保留编译器选择；更换编译器应使用新的构建目录。

## 3. 找到本题的实现边界

例如，定位 Append 的所有挖空区间：

```sh
rg -n 'LAB-S06\.Q02:.*-BEGIN' libs
```

区间以 `LAB-S06.Q02:Rnn-BEGIN` 和配对的 `END` 注释标记。同一题可能跨文件，同一文件也可能包含不同题的算法。先读函数声明、参数类型和相邻的给定结构，再修改本题区间。

[manifest](../../labs/manifest.json) 的 `questions[].regions` 记录实际区间、函数和文件。[题库清单](question-bank.json) 记录学习范围与验收要求。区间编号允许有空号；不要把编号连续性当作完成条件，也不要为便于查找而重编号。

## 4. 先用一个小例子解释预期

在写代码前，用纸笔或测试中的固定输入回答三个问题：

1. 调用前有哪些状态，哪些输入由调用方提供？
2. 成功时应返回什么，哪些状态可以改变？
3. 每个可能失败的位置，应保留什么、释放什么？

行流题记录每次 `open/next/rescan/close`；并发题用确定的事件顺序和屏障；持久化题记录写入、同步、发布和回收事件。仅比较最终结果容易漏掉提前读取、丢失唤醒或错误发布。

## 5. 按里程碑实现与检查

各题指南给出本题的分步目标。先处理最小输入，再加入边界、失败和重复调用。保留公共接口、字节格式、给定资源管理及原有错误约定。

当测试报告其他题的 `LAB-...` 时，先检查测试是否跨越了题目边界。独立测试需要受控依赖；尚未提供的测试端口应由课程维护者补齐。独立测试使用受控依赖，并保留其他题的初始状态。

## 6. 理解验收结果

Append 和 Unique 已有独立测试注册。实现后可运行：

```sh
python3 labs/run.py unit S06.Q02
python3 labs/run.py unit S06.Q03
```

初始未实现的版本会失败。其他 81 题目前缺少完成的独立验收注册或验证；指南中的测试文件链接是素材，可能包含跨题用例。`unit` 对缺少注册的题目会报告错误或未执行，不会计分。

| 结果 | 可以得出的结论 |
|---|---|
| 编译通过 | 接口、链接和编译约束满足；算法正确性仍需测试 |
| 本题全部具名测试通过 | 本次执行覆盖的本题验收通过 |
| 没有注册、零匹配、跳过或异常退出 | 没有取得本题通过证据 |
| 课程文件中的若干题通过 | 这些题取得分数；不自动说明完整数据库可运行 |

提交练习时，说明完成的题号、实现思路、验证用例和仍存在的限制。并发或持久化题应附关键事件顺序；执行题应说明 EOF、重扫和失败清理行为。

## 7. 再考虑组合运行

完成多题后，可用课程文件组织选题：

```sh
python3 labs/run.py selection --file labs/selections/sample-10.json
python3 labs/run.py plan --profile db-basic-rc
```

`plan` 只读展开组合需要的题集，不运行数据库。`db-basic-rc`、`db-relational`、`db-reference` 的默认要求分别为 46、76、83 题；真实能力接线和数据库组合验收仍待补齐。CLOCK/LRU 可以满足同一替换接口，其他算子是否可替换需看各自适用条件。

当前验证范围见 [验证记录](../../labs/verification.json)。
