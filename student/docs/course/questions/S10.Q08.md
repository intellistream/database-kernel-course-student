# S10.Q08 静态检查点接纳与排空

[返回阶段指南](../stages/S10.md)｜[题目总览](../README.md)

验收状态：本题的独立测试登记尚待补齐；现有测试只作素材，夹具名只表示契约。

## 这题要解决什么

静态 checkpoint 的目标是获得无新事务进入、旧事务可结束的静止点，再交给既有协调器持久化。它通过全 Session/API 接纳租约关闭新工作；SQL 入口只把单独的 `CREATE STATIC_CHECKPOINT` 识别为此操作，含该静态命令和其他语句的脚本须预检拒绝。空闲会话不阻塞，已接纳工作可排空；超时或失败必须重新开放接纳。它不同于 S10.Q07 的普通 fuzzy checkpoint。

## 开始前读懂什么

阅读 admission gate 的 lease、drain 和 timeout 语义，Session/API 各命令入口及 SQL parser 对 `CREATE STATIC_CHECKPOINT` 的 token/script 预检；理解 ProcArray 是排空后的权威活动 XID 复核来源。普通 `CHECKPOINT` 仍按普通 SQL 脚本语义处理；其 WAL/control 发布顺序由上一题复用。

## 先走通一个小例子

T1 已持接纳租约并执行，T2 在关门后新开始命令应被拒绝；T1 可以完成，空闲 session 不应阻塞。`CREATE TABLE t (...); CREATE STATIC_CHECKPOINT;` 这类含静态命令的混合脚本应在执行前整体拒绝，不能留下前半段效果；普通 `CHECKPOINT` 不触发这项静态命令预检。若 drain 超时或检查点失败，租约门恢复开放，随后新命令可进入。

## 分步实现

1. 为所有会话/API 入口取得和释放接纳 lease。
2. 在执行前识别单独的 `CREATE STATIC_CHECKPOINT`，拒绝含该静态命令的 mixed script，并施加 Idle 限制。
3. 关闭接纳，等待已接纳工作排空，按 timeout 返回明确结果。
4. 排空后复核权威活动 XID，调用静止模式协调器，并在所有退出路径开放闸门。

## 必须守住的约束

- 拒绝新工作但允许旧事务结束；空闲会话不能成为阻塞者。
- 含 `CREATE STATIC_CHECKPOINT` 的混合脚本不得产生部分效果；普通 `CHECKPOINT` 不在这项静态预检范围内。
- 超时、错误和异常展开都释放屏障；排空后的活动事务复核不能省略。

## 怎样验证

覆盖拒新允许旧事务结束、空闲会话不阻塞、含 `CREATE STATIC_CHECKPOINT` 的混合脚本无部分效果、超时/失败后恢复接纳。现有 [static_checkpoint_test.cpp](../../../libs/engine/tests/static_checkpoint_test.cpp) 与 [checkpoint_test.cpp](../../../libs/recovery/tests/checkpoint_test.cpp) 是素材；独立注册待补齐。

## 延伸阅读
