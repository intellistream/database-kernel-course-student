# S02.Q10 目录管理与表 DDL

## 这题要解决什么

目录是表身份和模式的权威来源；CREATE/DROP TABLE 必须在名称、OID、快照、持久映像和物理关系之间保持一致。

## 开始前读懂什么

OID 的单调分配、目录快照不可变性、候选目录映像的原子发布，以及表元数据与物理关系身份。索引专有 DDL 在 S03.Q08。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-CATALOG、F-IO，它们说明验收输入/端口边界，并不意味着仓库中普遍已有同名可直接实例化的类。阅读相关知识只是建立语境，不要求先完成关联题目。

## 先走通一个小例子

创建同名表应被拒绝，OID 耗尽也应清楚失败。创建后取到的旧快照不能因后续 DROP 改变；删除并重开后，目录身份与磁盘关系的对应仍应可核验。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 先校验名称、模式和表约束，分配未发布的候选 ID。
2. 构造新的目录代数与不可变快照，保留旧映像。
3. 协调 CREATE/DROP TABLE 的物理关系操作与目录发布。
4. 持久化并重开，核对 generation、OID 状态和关系身份。

每完成一步都回到 marker 附近检查调用方期待的是值、错误还是 guard/自有对象；不要把相邻题的策略或事务规则塞进这里。

## 必须守住的约束

失败不得发布候选目录或消耗可见身份；旧快照必须稳定。重复名称与 OID 耗尽都不是可忽略情况，DROP 后不得让目录仍指向旧物理对象。

## 怎样验证

验收必须覆盖以下全部检查：

- 重复名称与耗尽
- 失败不发布
- 旧快照稳定
- 删除/重开与目录身份一致
