# S10.Q12 数据库初始化与关闭协议

[返回阶段指南](../stages/S10.md)｜[题目总览](../README.md)

验收状态：本题的独立测试登记尚待补齐；现有测试只作素材，夹具名只表示契约。

## 这题要解决什么

数据库 open 必须区分新库、已干净关闭的库和遗留 `StartingUp/InCrashRecovery/ShuttingDown/InProduction` 的崩溃库，按依赖顺序组装服务，并尽早把已有库发布为 StartingUp。关闭则先阻止新工作、持久化必要状态，成功后才发布 Shutdown。初始化任一步失败都要让资源可清理且不把半成品冒充干净库。

## 开始前读懂什么

阅读 `Database::open/close`、启动控制状态、control store 的原子发布和恢复 runner 的前置条件。理解 `kInProduction` 不是“保证干净”，进程可能没执行析构；正常关闭需经过 `kShuttingDown` 并在最后发布 `kShutdown`。

## 从哪里开始

主要入口在 [database.cpp](../../../libs/engine/src/database.cpp) 与 [database_startup.cpp](../../../libs/engine/src/database_startup.cpp)，control 读写在 [control_store.cpp](../../../libs/wal/src/control_store.cpp)。根目录运行 `rg -n 'LAB-S10\.Q12:.*-BEGIN' libs`，共享文件只改对应 marker。

## 先走通一个小例子

对空目录初始化新库，建立控制映像和依赖后才接受会话；对已有 `kShutdown` 库，验证后直接组装正常服务。对遗留 `kInProduction` 库，先发布 StartingUp，再进 crash recovery，全部成功才发布 InProduction。关闭时若 CLOG/pages/WAL 任一同步失败，保持 shutting-down 可重试，绝不发布 Shutdown。

## 分步实现

1. 读取/分类 control，区分新库与已有非干净库，尽早发布 StartingUp。
2. 按依赖打开 WAL、原始存储、CLOG/目录、恢复或普通运行时服务。
3. 将所有权一次性移交到长期服务，失败时按反向生命周期清理。
4. 实现关闭的阻止新工作、持久化、ShuttingDown 与最终 Shutdown 发布顺序。

## 实现约束

- 新库不能与已有 StartingUp 库混淆；初始化成功后发布完成状态。
- 控制状态与启动/关闭调用顺序必须反映真实耐久边界。
- 关闭失败后资源可清理和重试，成功的 InProduction/Shutdown 只能在相应最后一步发布。

## 怎样验证

覆盖新库区别于已有 StartingUp 库、初始化各失败点、控制状态与启动/关闭调用顺序、失败时资源可清理。现有 [database_test.cpp](../../../libs/engine/tests/database_test.cpp) 与 [startup_recovery_test.cpp](../../../libs/recovery/tests/startup_recovery_test.cpp) 是素材；独立注册待补齐。
