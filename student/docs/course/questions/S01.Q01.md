# S01.Q01 页文件读写与分配

[返回阶段指南](../stages/S01.md)｜[题目总览](../README.md)

**独立测试：**待配置。

## 这题要解决什么

数据库把逻辑页交给上层之前，必须让它可靠地落在正确的段文件中，并让页数反映真实持久状态。这里建立后续堆、FSM 与目录都依赖的页 I/O 边界。

## 开始前读懂什么

页号到段文件的映射、定长页 I/O 的完整读写语义，以及“先落盘、后发布页数”的失败边界。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-IO，用于说明输入和依赖端口。

## 从哪里开始

本题源码入口是 [disk_manager.cpp](../../../libs/storage/src/disk_manager.cpp)、[file_layout.cpp](../../../libs/storage/src/file_layout.cpp)。优先定位 `FileDiskManager::open`、`read_page`、`write_page`、`allocate_page`，并检查 `RelationFileLayout::create_segment` 与 `publish_segment` 的创建/发布边界。实现范围为本题 marker 包围的区间；在仓库根目录检索：

```sh
rg -n 'LAB-S01\.Q01:.*-BEGIN' libs
```

## 先走通一个小例子

创建空关系后申请第一页，写入一个可识别的页首字节并同步；关闭再打开后，同一页号应读回该字节。请求当前末页之后的页号则应明确失败。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 先把页号、段号和段内偏移的换算及越界判定收拢到同一套规则。
2. 让打开路径发现已有段，页数只从完整且可接受的文件状态得出。
3. 把读、写、扩展和同步分别接到受检 I/O；短读或失败要带回错误。
4. 最后处理新段创建、发布、删除和关闭重开，确认页数在成功后才可见。

每步实现后检查调用方的返回类型、错误和对象生命周期。

## 实现约束

页号不能被静默截断；定长页的短读不是成功。扩展、创建或写入失败时，内存中的可见页数不得虚增。同步只承诺已成功写入的数据，关系删除要覆盖其段文件。

## 怎样验证

检查以下场景：

- 末页与越界
- 短读/写失败不发布虚假页数
- 关闭重开后页内容一致

现有测试源码可作为场景素材：[disk_manager_test.cpp](../../../libs/storage/tests/disk_manager_test.cpp)、[file_layout_test.cpp](../../../libs/storage/tests/file_layout_test.cpp)。测试范围见对应源码。独立注册待补齐；补齐后可在仓库根目录运行 `python3 labs/run.py unit S01.Q01`，并以实际报告为准。可先运行 `python3 labs/run.py list --stage 01` 核对登记状态。
