# S03.Q04 范围扫描与游标

[返回阶段指南](../stages/S03.md)｜[题目总览](../README.md)

**验收状态：**本题的 LAB 区间已挖空，但独立测试注册仍待补齐；当前运行 `unit` 的“未执行”不能视为通过。

## 这题要解决什么

索引扫描要把 SQL 风格的边界解释成连续的键范围，并跨越叶页返回每个候选。游标正确释放资源才能供执行器安全重用。

## 开始前读懂什么

下界/上界及开闭端点、复合键前缀范围、跨叶游标推进，以及 rescan 和提前结束时的 guard 生命周期。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-TREE，它们说明验收输入/端口边界，并不意味着仓库中普遍已有同名可直接实例化的类。阅读相关知识只是建立语境，不要求先完成关联题目。

本题源码入口是 [btree_relation.cpp](../../../libs/access/src/btree_relation.cpp)、[btree_scan.cpp](../../../libs/access/src/btree_scan.cpp)。优先定位 `BtreeScan::for_range`、`for_eq_range`、`next_candidate`、`previous_candidate`、`rescan`，以及 `Impl::before_lower`、`after_upper`、`step_leaf`。这些文件也含别题区域，只能编辑本题 marker 包围的区间；在仓库根目录检索：

## 先走通一个小例子

范围 `[a, a]` 只含等于 a 的条目；矛盾端点直接为空。重复键跨两个叶页时扫描不能漏项，提前停止后页 guard 释放；rescan 换范围后从新边界重新开始。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 先编码边界并判定空范围、方向和端点开闭。
2. 下降到初始叶，再在页内跳过下界前条目。
3. 跨 right/left 链推进并在每个候选上检查上界。
4. 实现 rebind/rescan 与早停清理，避免保留旧叶。

每完成一步都回到 marker 附近检查调用方期待的是值、错误还是 guard/自有对象；不要把相邻题的策略或事务规则塞进这里。

## 必须守住的约束

复合前缀不能被当作完整键比较；上、下界相等时开闭决定结果。跨叶重复键必须完整返回，EOF 与提前 close 后不得持有页 guard。

## 怎样验证

验收必须覆盖以下全部检查：

- 端点相等/矛盾
- 跨多叶重复键
- rescan 重设范围
- 提前结束释放守卫

现有测试源码可作为场景素材：[btree_scan_bounds_test.cpp](../../../libs/access/tests/btree_scan_bounds_test.cpp)、[btree_relation_scan_test.cpp](../../../libs/access/tests/btree_relation_scan_test.cpp)。它们可能跨题，不能替代本题的独立验收。独立注册待补齐；补齐后可在仓库根目录运行 `python3 labs/run.py unit S03.Q04`，并以实际报告为准。可先运行 `python3 labs/run.py list --stage 03` 核对登记状态。
