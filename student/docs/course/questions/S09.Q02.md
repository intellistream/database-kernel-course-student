# S09.Q02 RC/SI 快照协调与配置

[返回阶段指南](../stages/S09.md)｜[题目总览](../README.md)

验收状态：本题的独立测试登记尚待补齐；现有测试只作素材，夹具名只表示契约。

## 这题要解决什么

READ COMMITTED 要在每个数据命令重新取快照，SI 则在事务固定一个快照。题目还规定何时可 `SET` 隔离级别、BEGIN 的时点和 XID/epoch 的归属，防止一次配置变更偷偷影响已开始事务，或让下一事务继承上一次的 snapshot。

## 开始前读懂什么

阅读隔离级别枚举、`SnapshotCoordinator` 的捕获接口、状态机的 command/epoch，以及 Session 的配置入口。快照集合的底层算法属于 S09.Q01；这里的职责是挑对时间点和所有权。

## 从哪里开始

重点查看 [snapshot_coordinator.cpp](../../../libs/transaction/src/snapshot_coordinator.cpp)、[state.cpp](../../../libs/transaction/src/state.cpp) 和 [session.cpp](../../../libs/engine/src/session.cpp) 中的隔离设置与命令启动。运行 `rg -n 'LAB-S09\.Q02:.*-BEGIN' libs`，共享文件只改本题 marker。

## 先走通一个小例子

T1 以 RC 连续发两条查询，中间 T2 提交一行：第二条可看到新行。T1 以 SI 在 BEGIN 后捕获快照，重复查询仍看不到该行。若 T1 已执行第一条数据命令才 SET，或正处于 Failed/Implicit 不允许的状态，设置失败且原配置与快照不变。

## 分步实现

1. 把 RC 的命令快照和 SI 的事务快照分别存放并规定失效点。
2. 在 BEGIN 和首个数据命令处选择合法的捕获时机。
3. 核验 SET 仅在允许状态和数据访问之前生效。
4. 完成、回滚和新 epoch 时释放或重建快照，不跨事务复用。

## 必须守住的约束

- RC 与 SI 必须呈现可重复读差异。
- Failed、Implicit 及首条数据命令之后的非法设置都不得部分改动配置。
- 快照绑定正确的 XID/epoch，不能由 session 缓存泄漏到下一事务。

## 怎样验证

覆盖 RC 与 SI 可重复读差异、首条数据前 SET、失败/Implicit 状态拒绝、跨事务不复用。阅读 [visibility_test.cpp](../../../libs/transaction/tests/visibility_test.cpp)、[state_test.cpp](../../../libs/transaction/tests/state_test.cpp)、[session_test.cpp](../../../libs/engine/tests/session_test.cpp)；独立注册待补齐。

## 卡住时先想这几个问题

- 让 RC 第二条命令取新快照时，哪份旧快照必须已失效？
- 为什么 SI 的捕获点不应由每个执行器随意决定？

## 延伸阅读

在调试可重复读时，记录每条命令实际取得的 snapshot 标识和事务 epoch。若 RC 两条命令意外共用一份，或 SI 在下一事务仍取旧份，问题通常就在所有权和清理而非可见性公式。
