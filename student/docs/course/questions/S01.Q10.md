# S01.Q10 堆关系建立与打开

## 这题要解决什么

创建或打开堆关系时，堆页、FSM、注册表和物理身份必须作为一个整体协调。它避免失败遗留可见残片或打开错误关系。

## 开始前读懂什么

关系物理身份、HeapTable 与 FSM 的共同生命周期，以及创建/打开中的候选状态和发布点。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-IO、F-CATALOG，用于说明输入和依赖端口。

## 从哪里开始

本题源码入口是 [heap_table.cpp](../../../libs/access/src/heap_table.cpp)。优先定位 `HeapTable::create`、`open`、`ensure_initial_page`、`extend_page`、`persist_free_space_map`，并查看 `HeapSpaceRegistry::resolve`。实现范围为本题 marker 包围的区间；在仓库根目录检索：

```sh
rg -n 'LAB-S01\.Q10:.*-BEGIN' libs
```

## 先走通一个小例子

创建一个新表后应有可用的初始堆页和对应 FSM；初始化在中途失败时，之后用同名或同身份重试不应撞见可见半成品。打开已有关系时，身份不一致要被拒绝。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 先读取元数据和路径规则，区分新建与打开已有关系。
2. 将堆初始页、FSM 创建和注册放在一个可回退的创建过程。
3. 实现扩展和空关系第一次可插入页的协调。
4. 重开时校验物理身份并恢复 FSM，最后处理同步与回收。

每步实现后检查调用方的返回类型、错误和对象生命周期。

## 实现约束

失败前的候选不能发布到注册表；已有关系必须核对身份。FSM 与堆页不能只成功一边，空关系扩展后两者的页数认识要一致。

## 怎样验证

检查以下场景：

- 初始化失败不留下可见半成品
- 已有关系身份校验
- 空关系扩展与重开

现有测试源码可作为场景素材：[heap_table_test.cpp](../../../libs/access/tests/heap_table_test.cpp)、[heap_insert_test.cpp](../../../libs/access/tests/heap_insert_test.cpp)。测试范围见对应源码。独立注册待补齐；补齐后可在仓库根目录运行 `python3 labs/run.py unit S01.Q10`，并以实际报告为准。可先运行 `python3 labs/run.py list --stage 01` 核对登记状态。
