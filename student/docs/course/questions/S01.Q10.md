# S01.Q10 堆关系建立与打开

[返回阶段指南](../stages/S01.md)｜[题目总览](../README.md)

**验收状态：**本题的 LAB 区间已挖空，但独立测试注册仍待补齐；当前运行 `unit` 的“未执行”不能视为通过。

## 这题要解决什么

创建或打开堆关系时，堆页、FSM、注册表和物理身份必须作为一个整体协调。它避免失败遗留可见残片或打开错误关系。

## 开始前读懂什么

关系物理身份、HeapTable 与 FSM 的共同生命周期，以及创建/打开中的候选状态和发布点。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-IO、F-CATALOG，它们说明验收输入/端口边界，并不意味着仓库中普遍已有同名可直接实例化的类。阅读相关知识只是建立语境，不要求先完成关联题目。

## 从哪里开始

本题源码入口是 [heap_table.cpp](../../../libs/access/src/heap_table.cpp)。优先定位 `HeapTable::create`、`open`、`ensure_initial_page`、`extend_page`、`persist_free_space_map`，并查看 `HeapSpaceRegistry::resolve`。这些文件也含别题区域，只能编辑本题 marker 包围的区间；在仓库根目录检索：

```sh
rg -n 'LAB-S01\.Q10:.*-BEGIN' libs
```

## 先走通一个小例子

创建一个新表后应有可用的初始堆页和对应 FSM；初始化在中途失败时，之后用同名或同身份重试不应撞见可见半成品。打开已有关系时，身份不一致要被拒绝。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 先读取元数据和路径规则，区分新建与打开已有关系。
2. 将堆初始页、FSM 创建和注册放在一个可回退的创建过程。
3. 实现扩展和空关系第一次可插入页的协调。
4. 重开时校验物理身份并恢复 FSM，最后处理同步与回收。

每完成一步都回到 marker 附近检查调用方期待的是值、错误还是 guard/自有对象；不要把相邻题的策略或事务规则塞进这里。

## 必须守住的约束

失败前的候选不能发布到注册表；已有关系必须核对身份。FSM 与堆页不能只成功一边，空关系扩展后两者的页数认识要一致。

## 怎样验证

验收必须覆盖以下全部检查：

- 初始化失败不留下可见半成品
- 已有关系身份校验
- 空关系扩展与重开

现有测试源码可作为场景素材：[heap_table_test.cpp](../../../libs/access/tests/heap_table_test.cpp)、[heap_insert_test.cpp](../../../libs/access/tests/heap_insert_test.cpp)。它们可能跨题，不能替代本题的独立验收。独立注册待补齐；补齐后可在仓库根目录运行 `python3 labs/run.py unit S01.Q10`，并以实际报告为准。可先运行 `python3 labs/run.py list --stage 01` 核对登记状态。
