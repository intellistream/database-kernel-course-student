## 这题要解决什么

二级索引只有与堆变更和目录元数据同步时才可信。本题协调 DML 维护、索引 DDL 的发布/回退，以及物理身份审计。

## 开始前读懂什么

堆变更与二级索引的一致性、CREATE/DROP INDEX 的候选构建和目录发布，以及元数据物理身份审计。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-MUTATION、F-CATALOG、F-TREE，用于说明输入和依赖端口。

## 先走通一个小例子

堆行写入成功而索引维护失败时，结果必须由既定变更边界协调，不能报告完全成功。建索引在批建或发布失败后，用同名重试应可行；更新、删除后索引候选与堆内容一致。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 先从目录和堆描述构造每个索引的键及物理目标。
2. 让 INSERT/UPDATE/DELETE 调用相应索引维护，保留错误上下文。
3. CREATE INDEX 先批建候选物理关系，再发布目录；DROP 反向协调。
4. 审计目录身份、物理关系和索引内容，报告不可恢复的不匹配。

每步实现后检查调用方的返回类型、错误和对象生命周期。

## 实现约束

本题不能把堆成功等同于全操作成功；索引发布前不得在目录可见。失败后同名重试不能被孤儿物理关系阻塞，审计必须区分缺失、错身份与内容不一致。

## 怎样验证

检查以下场景：

- 堆成功而索引失败
- 建索引失败后同名重试
- 更新删除一致
- 身份不匹配报告
