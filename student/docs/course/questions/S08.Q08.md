# S08.Q08 事务等待与唤醒

[返回阶段指南](../stages/S08.md)｜[题目总览](../README.md)

验收状态：本题的独立测试登记尚待补齐；现有测试只作素材，F-TXN 是夹具契约名。

## 这题要解决什么

更新或锁操作有时需等待指定 XID 定案。等待器要先检查当前状态，再安全订阅唤醒，处理事务完成、中止、取消和对象关闭，避免在“检查到仍进行中”和“真正睡眠”之间漏掉通知，或在完成后永远睡下去。

## 开始前读懂什么

阅读 `XidWaiter` 的构造、等待 API 与它从 ProcArray/完成通知取得的信息；理解 CLOG 的最终状态与活动 slot 的区别；锁等待与 XID 等待共享“不能丢唤醒”的原则，但数据结构不同。

## 从哪里开始

唯一的挖空入口在 [xid_waiter.cpp](../../../libs/transaction/src/xid_waiter.cpp) 的 `XidWaiter::wait_for`。先对照同目录的 ProcArray 和 completion 接口，再在根目录执行 `rg -n 'LAB-S08\.Q08:.*-BEGIN' libs`，不要扩大到其他 marker。

## 先走通一个小例子

T1 正在进行，T2 调用等待。T2 建立等待后，T1 提交并发布完成，T2 被唤醒并读取终态。再试 T1 在 T2 注册前已中止：T2 应直接返回而不等待。关闭或取消发生时，观察等待者解除而不是把未完成误报为提交。

## 分步实现

1. 定义无效、已完成、进行中 XID 的快速路径。
2. 在检查与订阅之间建立不会丢通知的顺序。
3. 等待后重新读取权威状态，处理提交与中止。
4. 将取消、关闭和异常路径从等待集合中清理干净。

## 实现约束

- 通知只是重新检查信号，最终结论仍来自权威状态。
- 不得错过已发生的完成，也不得在虚假唤醒后报告完成。
- 等待者不能越过对象生命周期保存无效引用；取消必须可返回。

## 怎样验证

本题要求覆盖登记与提交交错、已完成 XID、取消与异常、不同 XID 唤醒隔离。现有 [xid_waiter_test.cpp](../../../libs/transaction/tests/xid_waiter_test.cpp) 是测试素材；独立测试注册尚待补齐。

## 思考题

- 完成通知恰好发生在状态检查后时，谁保证等待者仍能观察它？
- 被唤醒后为何还要再读一次事务状态？

## 延伸阅读

可用一个“完成发生在注册前、注册中、睡眠后”的三格时间线检查实现。每格最终都应返回同一权威终态，差别只能是是否真正阻塞过，不能产生依赖时序的结果。
