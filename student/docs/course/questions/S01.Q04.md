# S01.Q04 缓冲池调入与并发替换

[返回阶段指南](../stages/S01.md)｜[题目总览](../README.md)

**验收状态：**本题的 LAB 区间已挖空，但独立测试注册仍待补齐；当前运行 `unit` 的“未执行”不能视为通过。

## 这题要解决什么

缓冲池要把并发页面请求收敛为唯一映射，并安全地把磁盘页装入空闲或替换得到的帧。它是逻辑页访问与物理 I/O 的汇合点。

## 开始前读懂什么

页地址到帧的唯一映射、Frame 的 latch/pin/I/O 生命周期，以及缺页合并中的“加载中”状态。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-BUFFER、F-FRAME，它们说明验收输入/端口边界，并不意味着仓库中普遍已有同名可直接实例化的类。阅读相关知识只是建立语境，不要求先完成关联题目。

## 从哪里开始

本题源码入口是 [buffer_pool.cpp](../../../libs/storage/src/buffer_pool.cpp)、[frame.cpp](../../../libs/storage/src/frame.cpp)。优先定位 `BufferPool::Impl::fetch`、`try_cache_hit`、`install_miss`、`replace_miss`，再跟踪 `BufferMapping::begin_loading`、`insert`、`remap` 和 `Frame::try_claim_evictable`。这些文件也含别题区域，只能编辑本题 marker 包围的区间；在仓库根目录检索：

## 先走通一个小例子

两个线程同时请求同一未缓存页：磁盘端口只应看到一次读取，二者最后指向同一帧。已有命中页的读取不能触发读盘；替换路径失败时旧页仍能被找到并保持原 pin。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 先让命中路径在映射与 Frame 状态一致时增加引用并返回。
2. 为缺页设置可等待的加载占位，合并同页并发请求。
3. 从空闲帧或受害 guard 取得帧后，完成读盘、安装和映射发布的顺序。
4. 把读盘、声明或安装失败逐层回滚，唤醒等待者并恢复受害者。

每完成一步都回到 marker 附近检查调用方期待的是值、错误还是 guard/自有对象；不要把相邻题的策略或事务规则塞进这里。

## 必须守住的约束

同一页同一时刻只能有一个可见映射；命中不应读盘。映射、Frame 地址和 pin 必须成对更新；失败不能丢失旧映射、旧页或受害 guard。

## 怎样验证

验收必须覆盖以下全部检查：

- 同页并发调入唯一映射
- 命中不读盘
- 替换失败不丢失旧页和 pin

现有测试源码可作为场景素材：[buffer_pool_test.cpp](../../../libs/storage/tests/buffer_pool_test.cpp)、[frame_test.cpp](../../../libs/storage/tests/frame_test.cpp)。它们可能跨题，不能替代本题的独立验收。独立注册待补齐；补齐后可在仓库根目录运行 `python3 labs/run.py unit S01.Q04`，并以实际报告为准。可先运行 `python3 labs/run.py list --stage 01` 核对登记状态。
