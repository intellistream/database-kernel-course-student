## 这题要解决什么

AST 中的表达式还没有可执行类型和列位置；本题将它们置于语句上下文中定型、校验并为 DML 建立正确映射。

## 开始前读懂什么

表达式的输入类型、谓词必须为布尔值、外部参数定型，以及 INSERT/UPDATE 目标列与源列的映射。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-AST、F-CATALOG，用于说明输入和依赖端口。

## 从哪里开始

本题源码入口是 [binder.cpp](../../../libs/sql/src/binder.cpp)、[binder_scope.cpp](../../../libs/sql/src/binder_scope.cpp)、[binder_scope_internal.hpp](../../../libs/sql/src/binder_scope_internal.hpp)。优先定位 `bind_expression`、`bind_binary_expression`、`bind_boolean_expression`、`bind_cast_expression`、`bind_insert_query`，按表达式与语句位置分别阅读。实现范围为本题 marker 包围的区间；在仓库根目录检索：

## 先走通一个小例子

`WHERE 1` 应因非布尔谓词失败；带 NULL 的参数在有目标类型时被定型。INSERT 指定列顺序与表定义不同，绑定后的目标位置仍应对应正确列。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 先递归绑定字面量、列引用和参数，记录类型与来源。
2. 对算术、比较、布尔和 cast 插入合法的强制转换。
3. 绑定谓词、窗口表达式和 DML 源，分别检查位置约束。
4. 完成目标列重排和参数约束，确保结果能被后续计划安全拥有。

每步实现后检查调用方的返回类型、错误和对象生命周期。

## 实现约束

WHERE 只接受布尔语义；NULL 和参数不能长期无类型。赋值要对准目标列，窗口规则不能被普通表达式路径绕过；失败不得留下部分绑定的可执行语句。
