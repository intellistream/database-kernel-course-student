# S10.Q09 堆与 B+Tree 页重做

[返回阶段指南](../stages/S10.md)｜[题目总览](../README.md)

验收状态：本题的独立测试登记尚待补齐；现有测试只作素材，夹具名只表示契约。

## 这题要解决什么

恢复要将已验证的 heap/B+Tree WAL 物理应用到启动页缓存：按 opcode、FPI/delta 和 page LSN 决定跳过或原子发布候选页，处理多页 split、更新和缺/坏页。即使某事务后来是 loser，它的必要物理记录也必须重做；可见性由事务收尾决定，不能用“最终中止”跳过物理 UNDO 的替代品。

## 开始前读懂什么

阅读 dispatcher 的已验证路由、`StartupPageAccessPort` 的 `kReadExisting/kSkipExisting`、页 LSN 幂等和 FPI/WILL_INIT 规则。Heap/Btree 的业务日志由 S10.Q06 生成；本题不重新做不受信 WAL 的语义分发。

## 从哪里开始

入口在 [heap_startup_redo.cpp](../../../libs/recovery/src/heap_startup_redo.cpp) 与 [btree_startup_redo.cpp](../../../libs/recovery/src/btree_startup_redo.cpp)，具体页操作在 [heap_wal.cpp](../../../libs/recovery/src/heap_wal.cpp)、[btree_wal.cpp](../../../libs/recovery/src/btree_wal.cpp)，有界驻留/排空在 [recovery_page_cache.cpp](../../../libs/recovery/src/recovery_page_cache.cpp)。命令：`rg -n 'LAB-S10\.Q09:.*-BEGIN' libs`。

## 先走通一个小例子

一条 heap 更新记录到达已有较高 page LSN 的页，应跳过且不标脏；同一记录重复重放结果不变。对 `WILL_INIT` 或 FPI，端口用 skip-existing 取得替换页，先完成候选布局再发布和标脏。随后重放一个 loser 的插入物理记录：页仍需更新，稍后 CLOG 使该版本对 SQL 不可见。

## 分步实现

1. 根据已分发块选择页类型、读取模式和 LSN 跳过条件。
2. 在私有候选页上应用 FPI 或 delta/opcode，验证后才发布单页结果。
3. 按 WAL 块顺序处理多页 heap 更新和 Btree split，不持跨页租约。
4. 接入有界恢复缓存的标脏、逐出、排空与失败重试边界。

## 必须守住的约束

- 旧 LSN 跳过和重复重放必须幂等。
- 缺页/坏页场景按 FPI、WILL_INIT 与读取模式处理；失败不得标脏半页。
- 不按最终提交状态跳过 loser 的必要物理记录，不能用物理 UNDO 代替既有 MVCC 回滚。

## 怎样验证

覆盖旧 LSN 跳过、重复重放、跨页分裂与更新、缺页/坏页/FPI、不按最终提交状态跳过物理记录。素材：[heap_wal_test.cpp](../../../libs/recovery/tests/heap_wal_test.cpp)、[btree_wal_test.cpp](../../../libs/recovery/tests/btree_wal_test.cpp)、[recovery_page_cache_test.cpp](../../../libs/recovery/tests/recovery_page_cache_test.cpp)；独立注册待补齐。

## 卡住时先想这几个问题

- FPI/WILL_INIT 为什么能避免读取一个不可信的旧页，而普通 delta 不能？
- loser 页面记录若不重做，之后提交事务引用的页面布局会怎样错位？

## 延伸阅读

多页记录不持跨页租约意味着一次中断可能只发布前面若干块；这不是错误，因为重新启动会靠各页 LSN 或 FPI 安全跳过/重做。不要为追求一次性而把恢复缓存锁成无界资源。
