# S09.Q01 ProcArray 快照与回收边界

[返回阶段指南](../stages/S09.md)｜[题目总览](../README.md)

验收状态：本题的独立测试登记尚待补齐；现有测试只作素材，夹具名只表示契约。

## 这题要解决什么

快照要描述“当前哪些 XID 可能仍影响读”，而回收边界要描述“最老读者还可能看见什么”。ProcArray 在并发登记、完成、槽位复用时产出 xmin、xmax 和活动集合；它若漏掉刚登记的事务或过早抬高最老边界，旧快照就会读错或让 VACUUM 过早回收。

## 开始前读懂什么

阅读 `Snapshot` 的 xmin/xmax 与 active XID 表示、ProcSlot 的 snapshot xmin 广告、以及 XID 环绕比较。读者快照与事务登记共享同一数组，但事务状态转换不是本题要补的算法。

## 从哪里开始

从 [proc_array_snapshot.cpp](../../../libs/transaction/src/proc_array_snapshot.cpp) 的快照捕获、最老边界与 slot 复用相关函数开始，同时查看 [proc_array.hpp](../../../libs/transaction/include/db/transaction/proc_array.hpp) 的返回契约。根目录命令：`rg -n 'LAB-S09\.Q01:.*-BEGIN' libs`；仅处理这些 marker。

## 先走通一个小例子

T1 已登记 XID 10 并广告 xmin 10，T2 捕获快照得到可区分 T1 的集合。T1 完成同时 T3 复用槽位并登记 XID 11，新的快照必须能看见 11，旧快照仍保留自己的边界。只要 T1 的读者尚在，维护端看到的 oldest xmin 不得越过 10。

## 分步实现

1. 在受保护的数组视图上收集有效活动 slot，并按 XID 规则形成 xmin/xmax。
2. 处理登记和完成交错，使槽位复用不会把新事务当成旧事务。
3. 汇总各 slot 广告的读者下界，得到最老可回收边界。
4. 对空集合、无效 XID 与并发变化采用接口规定的保守结果。

## 必须守住的约束

- 并发登记/完成不能让快照漏掉新事务或重复旧事务。
- 最老读者阻止过早回收，宁可保守不能激进。
- XID 比较必须沿用给定环绕规则，slot lease 和广告在完成后需清除。

## 怎样验证

覆盖并发登记/完成、快照集合边界、复用不能漏新事务、最老读者阻止过早回收。现有 [proc_array_test.cpp](../../../libs/transaction/tests/proc_array_test.cpp) 与 [visibility_test.cpp](../../../libs/transaction/tests/visibility_test.cpp) 是素材；独立注册待补齐。

## 卡住时先想这几个问题

- 快照采样期间槽位从 T1 变成 T3，怎样证明不会把两者拼成一个事实？
- 维护者为何应取所有活动读者中最保守的 xmin？

## 延伸阅读

检查并发逻辑时，不妨把每个 slot 的读取看作可能跨越一次复用；快照算法应依赖接口给出的稳定观察方式，而不是先读 XID、稍后再假定它仍属于同一个 session。
