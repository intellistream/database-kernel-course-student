# S08.Q02 XID 与活动事务登记

[返回阶段指南](../stages/S08.md)｜[题目总览](../README.md)

验收状态：本题的独立测试登记尚待补齐；现有测试只作素材，F-TXN 是夹具契约名。

## 这题要解决什么

事务一旦需要持久化身份，就必须分到合法 XID，并在共享 ProcArray 中可被其他事务发现。题目处理分配前沿、ProcSlot 租约和登记撤销；快照内容的计算留给后续题。目标是在并发进入、退出和失败时不复用身份，也不留下幽灵活动事务。

## 开始前读懂什么

阅读 Xid 的无效值与环绕比较规则、`ProcSlot` 的 lease 所有权，以及 ProcArray 对 session/slot 的绑定。分配器先产生候选，登记成功才发布该候选；不要把快照算法当作本题前置。

## 从哪里开始

查看 [xid.cpp](../../../libs/transaction/src/xid.cpp) 的 `XidGenerator::allocate`，再读 [proc_slot.cpp](../../../libs/transaction/src/proc_slot.cpp) 的 `create/assign_xid/clear_xid`、[proc_array.cpp](../../../libs/transaction/src/proc_array.cpp) 的登记与验证，最后看 [manager.cpp](../../../libs/transaction/src/manager.cpp) 的 `assign_xid`。命令：`rg -n 'LAB-S08\.Q02:.*-BEGIN' libs`。

## 先走通一个小例子

两个 session 获得不同 lease。第一个为写入申请 XID 并登记，第二个此时应能观察到它活动；第一个结束时先按所有权撤销并清空槽位，随后同一槽位才可复用。若分配或登记失败，观察 next frontier 与活动集合都没有虚假发布。

## 分步实现

1. 固定无效 XID、比较和分配边界的拒绝规则。
2. 让 ProcSlot 的创建、分配、清空都核验当前 lease。
3. 在 ProcArray 锁定范围内完成 session 登记、XID 宣告和撤销。
4. 由 Manager 串起候选 XID 与共享登记，失败时保持前沿和槽位一致。

## 实现约束

- 分配失败不发布；租约不能被别的 session 使用。
- XID 边界与比较必须使用给定标识类型的规则。
- 并发登记、释放不得遗漏活动项，快照 xmin 的广告/撤销也必须随槽位生命周期收尾。

## 怎样验证

覆盖分配失败不发布、租约所有权、XID 边界、并发登记与释放不遗漏。现有素材是 [xid_test.cpp](../../../libs/transaction/tests/xid_test.cpp)、[proc_slot_test.cpp](../../../libs/transaction/tests/proc_slot_test.cpp)、[proc_array_test.cpp](../../../libs/transaction/tests/proc_array_test.cpp) 和 [manager_test.cpp](../../../libs/transaction/tests/manager_test.cpp)；独立注册待补齐。

## 思考题

- 哪一步失败后，别的线程会误把一个尚未真正拥有的 XID 当作活动？
- 槽位复用前，旧 XID 和旧 snapshot xmin 是否都已不可见？

## 延伸阅读

调试时可在登记前后分别观察 slot 的 lease、XID 与 xmin 字段；只要其中任一旧值仍被读取，就说明复用边界尚未真正完成。分配前沿的推进也应同这组观察分开验证。
