# S09.Q06 SSI 冲突图与提交裁决

[返回阶段指南](../stages/S09.md)｜[题目总览](../README.md)

验收状态：本题的独立测试登记尚待补齐；现有测试只作素材，夹具名只表示契约。

## 这题要解决什么

SSI 将读集与写入匹配成 rw 依赖边，再结合并发与提交顺序识别危险结构。它不要求锁住所有读写，却必须在确有序列化风险时选定失败受害者；无冲突或不重叠的事务应正常提交。裁决后还需保留必要边，避免后续提交看不到关键历史。

## 开始前读懂什么

先读 SSI 事务状态、rw edge、commit sequence 和 lifecycle 的公开字段；理解边代表 reader→writer 的反依赖，而非普通锁等待。S09.Q05 负责收集读集，这里不能假设有隐藏的自动冲突发现。

主要文件是 [ssi_conflict_graph.cpp](../../../libs/transaction/src/ssi_conflict_graph.cpp)、[ssi_commit_order.cpp](../../../libs/transaction/src/ssi_commit_order.cpp)、[ssi.cpp](../../../libs/transaction/src/ssi.cpp)、[ssi_lifecycle.cpp](../../../libs/transaction/src/ssi_lifecycle.cpp) 和 `ssi_state.hpp`。定位命令：`rg -n 'LAB-S09\.Q06:.*-BEGIN' libs`。

## 先走通一个小例子

两个事务各读对方将写的行，随后各写自己的行，形成写偏斜所需的 rw 依赖。让它们重叠并按不同顺序试图提交：规则应阻止规定的一方。再试只有一条边或事务不重叠的案例，观察两者均可提交，图中边按安全时机才清理。

## 分步实现

1. 从已匹配读写事件建立双向可查询的 rw 边。
2. 记录并发区间和提交次序，区分已提交与仍活动节点。
3. 检查危险结构或环，按给定规则选择可失败事务。
4. 在 commit、abort 和 GC 生命周期中保留或删除图状态，保证之后的裁决仍正确。

## 实现约束

- 写偏斜必须被阻止，但无冲突事务不能因保守实现被拒绝。
- 已提交/重叠边界和提交顺序是裁决输入，不能只看当前活动集合。
- 清理不能丢失仍参与危险结构的边，也不能留下已无引用的永久节点。

## 怎样验证

覆盖写偏斜被阻止、无冲突可提交、已提交/重叠事务边界、边清理不丢必要冲突。测试素材为 [ssi_conflict_graph_test.cpp](../../../libs/transaction/tests/ssi_conflict_graph_test.cpp)、[ssi_commit_order_test.cpp](../../../libs/transaction/tests/ssi_commit_order_test.cpp)、[ssi_test.cpp](../../../libs/transaction/tests/ssi_test.cpp)；独立注册待补齐。
