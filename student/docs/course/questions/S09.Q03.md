# S09.Q03 元组可见性与索引版本分类

[返回阶段指南](../stages/S09.md)｜[题目总览](../README.md)

验收状态：本题的独立测试登记尚待补齐；现有测试只作素材，夹具名只表示契约。

## 这题要解决什么

堆扫描、按 RID fetch 和唯一索引检查都必须根据 creator/modifier、命令 ID、CLOG 和快照解释一个版本：它对当前读者可见、仍待等候、已经死亡，还是可作为索引候选。SQL 可见性与物理 redo 是不同层，不能因为事务最终中止就跳过恢复中的必要物理记录。

## 开始前读懂什么

阅读 tuple header 的创建/删除信息、snapshot 的边界与 active 集合、CLOG 查询，以及 heap RID 到索引版本分类接口。理解“自己的写入”是 command id 和当前事务共同决定的，不只是 CLOG 显示进行中。

## 从哪里开始

核心判断在 [visibility.cpp](../../../libs/transaction/src/visibility.cpp)；堆 fetch/scan 的接入位于 [heap_fetch.cpp](../../../libs/access/src/heap_fetch.cpp)、[heap_scan.cpp](../../../libs/access/src/heap_scan.cpp)，索引 RID 分类在 [heap_index_tid.cpp](../../../libs/access/src/heap_index_tid.cpp)。执行 `rg -n 'LAB-S09\.Q03:.*-BEGIN' libs`。

## 先走通一个小例子

读者 R 持有旧快照。T1 在快照后提交一个插入，R 不可见；当前命令由 R 自己插入的版本可见。另一个事务锁住或更新同一 RID 时，分类应告诉调用方等待、跟随新版本或跳过，而不是把所有“非可见”折叠成删除。

## 分步实现

1. 把 creator 与 modifier 分别按自己、进行中、提交、中止和快照边界分类。
2. 结合 command id 处理当前事务的插入、更新和删除。
3. 将判定接入 fetch 和 scan，保留调用方需要的等待/继续信息。
4. 为索引 RID 输出稳定的生命周期分类，避免唯一性检查误判。

## 实现约束

- 自己的写入、他人待决/提交/回滚与旧快照都要区分。
- 锁标记和更新标记不能被误作最终删除。
- SQL 可见性不得替代物理 redo 的 page-LSN/FPI 决策。

## 怎样验证

检查自己的写入、他人待决/提交/回滚、旧快照、锁标记与更新标记及 SQL 与物理重放不同。测试素材：[visibility_test.cpp](../../../libs/transaction/tests/visibility_test.cpp)、[heap_fetch_test.cpp](../../../libs/access/tests/heap_fetch_test.cpp)、[btree_unique_test.cpp](../../../libs/access/tests/btree_unique_test.cpp)；独立注册待补齐。

## 思考题

- 一个版本对旧快照不可见，是否必然说明它永远不可见？
- 当前事务自己的删除为何需要命令 ID，而不能只看 XID？

## 延伸阅读

给每种分类准备一行最小事实表：当前 XID、命令 ID、creator、modifier、CLOG 与快照位置。这样能区分真正的可见性错误和调用者把“等待”误当“不可见”的错误。
