# S01.Q06 空闲空间映射 FSM

## 这题要解决什么

堆表插入需要快速找到“可能够用”的页，而无需逐页探测。FSM 用保守的空间分类缩小查找范围，并把信息安全地保存下来。

## 开始前读懂什么

FSM 的空间等级是保守提示、树节点最大值向上传播，以及磁盘页数与持久化映像之间的关系。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-IO、F-HEAP，用于说明输入和依赖端口。

## 从哪里开始

本题源码入口是 [free_space_map.cpp](../../../libs/storage/src/free_space_map.cpp)。优先定位 `FreeSpaceMap::open`、`update`、`find_page`、`record_and_find`、`persist`，并理解 `FreeSpaceTree::find`、`update`、`grow` 的树状态。实现范围为本题 marker 包围的区间；在仓库根目录检索：

```sh
rg -n 'LAB-S01\.Q06:.*-BEGIN' libs
```

## 先走通一个小例子

记录某页有足够空间后，以较小请求查找应命中候选；实际插入发现它陈旧时，更新后要继续寻找或报告无页。关闭重开后，记录的分类仍应与持久状态一致。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 明确字节数到分类的边界，并拒绝无效的空闲字节。
2. 实现叶子更新及祖先最大值传播，处理树增长和未跟踪页。
3. 让 find 返回满足请求的候选而非承诺可插入的页。
4. 将 record_and_find、打开和持久化串联，保证陈旧信息能被修正。

每步实现后检查调用方的返回类型、错误和对象生命周期。

## 实现约束

FSM 不能声称超过实际页空间；没有候选应是正常结果。树的最大值必须与子树一致，持久化失败不能发布新的映像。

## 怎样验证

检查以下场景：

- 多层最大值传播
- 无可用页
- 陈旧候选与重开后一致

现有测试源码可作为场景素材：[free_space_map_test.cpp](../../../libs/storage/tests/free_space_map_test.cpp)。测试范围见对应源码。独立注册待补齐；补齐后可在仓库根目录运行 `python3 labs/run.py unit S01.Q06`，并以实际报告为准。可先运行 `python3 labs/run.py list --stage 01` 核对登记状态。
