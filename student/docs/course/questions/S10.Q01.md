# S10.Q01 WAL 环形缓冲

[返回阶段指南](../stages/S10.md)｜[题目总览](../README.md)

验收状态：本题的独立测试登记尚待补齐；现有测试只作素材，夹具名只表示契约。

## 这题要解决什么

WAL 生产者先在有限环形缓冲预留空间，再写入并按顺序发布；写盘者只能消费连续完成的前缀。多个生产者、回绕和满环背压使“已预留”与“已可读”不能混为一谈。关闭或取消时还要唤醒被空间或发布顺序阻塞的线程。

## 开始前读懂什么

阅读 ring 的 reserve/publish/consume 语义、LSN 与物理槽位映射、连续发布 frontier 和关闭状态。记录编码、磁盘分段写入属于其他题；这里缓冲区只保存字节和生命周期。

## 从哪里开始

从 [ring_layout.cpp](../../../libs/wal/src/ring_layout.cpp) 理解 LSN 到环位置的计算，再读 [ring_buffer.cpp](../../../libs/wal/src/ring_buffer.cpp) 的空间预留、发布、读取和关闭路径。执行 `rg -n 'LAB-S10\.Q01:.*-BEGIN' libs`，只改本题 marker。

## 先走通一个小例子

环容量仅容两条小记录。P1 预留第一段但尚未发布，P2 预留第二段并先写完；消费者仍只能看到 P1 之前的连续边界。P1 发布后两条才可读。再使写入跨越环尾，确认读取字节顺序不变；环满时新生产者等待，消费者推进后被唤醒。

## 分步实现

1. 实现长度/对齐检查和 LSN、物理环位的无歧义换算。
2. 区分预留前沿与连续发布前沿，处理乱序完成的生产者。
3. 实现消费者取得连续前缀、消费推进和回绕拷贝。
4. 在满环、取消和关闭路径唤醒所有适当等待者。

## 实现约束

- 未完成预留绝不能让可读边界越过它。
- 满环背压不得覆盖尚未消费的数据。
- 取消/关闭不应留下永久等待或发布一个半写入的记录。

## 怎样验证

覆盖跨环边界、并发未完成预留不越过发布、满环背压、取消/关闭。使用 [ring_buffer_test.cpp](../../../libs/wal/tests/ring_buffer_test.cpp) 作现有测试素材；独立注册待补齐。

## 思考题

- P2 先完成时，消费者凭什么知道 P1 的字节是否已经完整？
- 消费位置推进后，哪些空间才真正可以再次预留？
