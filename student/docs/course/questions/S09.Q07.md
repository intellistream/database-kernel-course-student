# S09.Q07 HOT 修剪与 VACUUM

[返回阶段指南](../stages/S09.md)｜[题目总览](../README.md)

验收状态：本题的独立测试登记尚待补齐；现有测试只作素材，夹具名只表示契约。

## 这题要解决什么

HOT 链中的旧版本不是一完成就可覆盖：仍有旧快照的读者可能需要它。VACUUM 依据 oldest_xmin 判断可回收项，修剪/重定向版本链，收集 dead TID，先让索引清理，再复用 heap 槽位并更新 FSM。重复维护要收敛，而不是损坏仍存活的元组。

## 开始前读懂什么

理解 S09.Q01 的回收下界、HOT 链和索引 TID 引用；阅读 heap/btree maintenance 的计划与执行接口，以及 FSM 表示的可用空间。事务可见性和更新生成链是前置知识，其他实现不需复制。

## 从哪里开始

从 [heap_maintenance.cpp](../../../libs/access/src/heap_maintenance.cpp) 的判定、链处理、空间统计开始，接着读 [btree_maintenance.cpp](../../../libs/access/src/btree_maintenance.cpp) 的 dead TID 清理，最后看 [maintenance_executor.cpp](../../../libs/engine/src/maintenance_executor.cpp) 的编排。命令：`rg -n 'LAB-S09\.Q07:.*-BEGIN' libs`。

## 先走通一个小例子

页上有 r0→r1 的 HOT 链，旧快照 xmin 仍小于 r0 的死亡边界时，maintenance 只能保留可达版本。读者结束后，计划可收集 r0 的 dead TID；索引清理成功后才回收槽位并增加 FSM 空间。再运行一次，观察页面、索引和统计不发生第二次破坏。

## 分步实现

1. 用 oldest_xmin 分类活、死、暂不可回收版本。
2. 计算保留链、可重定向项与 dead TID，先形成计划再发布页面变化。
3. 协调索引删除与 heap 槽位复用的顺序。
4. 更新 FSM 和活元组统计，并为失败或重复调用保持幂等。

## 实现约束

- 旧快照保护优先于空间回收。
- 索引必须先清理，才能复用其可能仍指向的 RID。
- 重复维护应幂等，空间统计和活元组集合必须完整一致。

## 怎样验证

覆盖旧快照保护、索引先清理再复用 RID、重复维护幂等、空间统计与活元组完整。素材：[heap_maintenance_test.cpp](../../../libs/access/tests/heap_maintenance_test.cpp)、[btree_maintenance_test.cpp](../../../libs/access/tests/btree_maintenance_test.cpp)、[heap_update_test.cpp](../../../libs/access/tests/heap_update_test.cpp)；独立注册待补齐。
