# S08.Q07 Backend 与 Session 事务协调

[返回阶段指南](../stages/S08.md)｜[题目总览](../README.md)

验收状态：本题的独立测试登记尚待补齐；现有测试只作素材，F-TXN、F-MUTATION 是夹具契约名。

## 这题要解决什么

Session 是 SQL 命令边界，TransactionBackend 保存本地事务事实。题目把两者和 `CommandScope` 接起来：自动与显式事务都要获取正确快照，记录自己的写入，命令失败时原子地进入正确状态，并在提交、回滚或析构时完成资源收尾，使下一事务可正常开始。

## 开始前读懂什么

阅读 `Session` 的 begin/commit/rollback/start/finish 命令接口、`TransactionBackend` 的本地状态，以及 command snapshot 的生存期。物理堆修改走既有端口；本题不要求预先实现那些页面算法。

## 从哪里开始

先看 [command_scope.cpp](../../../libs/engine/src/command_scope.cpp) 的构造与 `finish_success/finish_failure`，再读 [session.cpp](../../../libs/engine/src/session.cpp) 的命令入口，最后看 [backend.cpp](../../../libs/transaction/src/backend.cpp) 的显式事务与写入标记，以及服务编排文件。命令：`rg -n 'LAB-S08\.Q07:.*-BEGIN' libs`。

## 先走通一个小例子

在自动提交中执行一条成功 DML：创建 scope、取命令快照、标记持久化写、完成并恢复 idle。然后在 `BEGIN` 内让 COPY 失败：scope 应结束失败，显式事务留下 Failed，后续只允许回滚；回滚后下一条自动命令不应继承旧快照、旧 heap target 或失败标记。

## 分步实现

1. 建立 Session 与 Backend 的单一归属和创建路径。
2. 让 scope 在成功/失败两个出口各执行一次相符的 finish。
3. 接入显式命令、自动命令、快照和 persistent/unlogged write 标记。
4. 实现 commit、rollback、析构时的完成错误传播与本地状态清理。

## 必须守住的约束

- DML/COPY 失败必须进入正确状态，不能只返回错误文本。
- 自己的写入需要在同一后端可见；跨事务不得复用局部快照或目标。
- 完成失败不假成功，析构和下一事务必须留下可恢复的一致状态。

## 怎样验证

检查 DML/COPY 失败进入正确状态、自己的写入、完成错误不假成功、下一事务可恢复。阅读 [backend_test.cpp](../../../libs/transaction/tests/backend_test.cpp)、[session_test.cpp](../../../libs/engine/tests/session_test.cpp)、[query_test.cpp](../../../libs/engine/tests/query_test.cpp)；独立验收注册待补齐。

## 卡住时先想这几个问题

- 命令执行失败后，scope 是否仍会走一次且只走一次的收尾？
- 一个临时快照在何时失效，何时必须由显式事务持有？

## 延伸阅读

建议把一次命令的资源归属画成 Session、Backend、CommandScope 三者之间的短生命周期：错误路径和成功路径都应回到同一个可验证状态，而不是由析构器偶然补救。
