# S04.Q02 列需求与条件放置

[返回阶段指南](../stages/S04.md)｜[题目总览](../README.md)

## 这题要解决什么

SELECT 输出列很少而排序、过滤仍引用其它列时，过早裁剪会让排序键或残余谓词消失。例如只选 `name` 却按 `score` 排序、用 `age` 过滤，子计划仍须传递三列。

完成后，你能收集所有消费者的列需求、重映射表达式位置，并在语义允许处放置投影和过滤。

## 先走通一个小例子

投影只输出 `name`，排序用 `score`，过滤用 `age>18`。裁剪后的子计划仍须保留 name、score、age，最终才删除隐藏列。

## 分步实现

- 从输出、排序和残余谓词收集列引用。
- 向子节点传播需求，并建立旧位置到新位置的映射。
- 重写表达式中的输入列位置。
- 仅在输入具备所需列且语义允许时下推。

## 必须守住的约束

- 隐藏排序列和残余谓词列不能因未出现在 SELECT 列表而丢失。
- 重排列后每个 InputColumn 必须指向新描述符的正确位置。
- 本题不决定 JOIN 条件放置。

## 怎样验证

验收必须覆盖：重复/重排列；隐藏排序列；保留残余谓词需要的列；裁剪前后结果等价。

现有素材 [lowering_test.cpp](../../../libs/planner/tests/lowering_test.cpp)、[preprocess_test.cpp](../../../libs/planner/tests/preprocess_test.cpp) 可能跨越多题，不能把它们当作本题已经注册的隔离测试。完成后按课程规定的单元入口验证；独立注册状态是 `pending-isolated-test-registration`。

## 卡住时先想这几个问题

- 该列是否在排序、过滤或表达式内部仍被读取？
- 重写后每个列位置还能对应原来的值吗？
