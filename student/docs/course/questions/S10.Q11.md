# S10.Q11 启动分析与恢复调度

[返回阶段指南](../stages/S10.md)｜[题目总览](../README.md)

验收状态：本题的独立测试登记尚待补齐；现有测试只作素材，夹具名只表示契约。

## 这题要解决什么

启动恢复先分析 control 与 WAL 验证结果，决定是否恢复及 redo 起止范围；随后按物理顺序让 dispatcher 验证资源管理器/opcode，再协调页 redo 和持久状态收尾。完整前缀后的截断尾部可由唯一允许的管理器路径修复，中部损坏、缺段和未知 opcode 必须停止；只有整个过程成功才发布运行状态。

## 开始前读懂什么

阅读 control 的数据库状态与 redo/checkpoint LSN 约束、`WalStartupValidation`、`RecoveryDispatcher` 路由结果、startup runner 的服务所有权。Reader 只做物理 framing；dispatcher 是不受信 WAL 的语义验证入口。

## 从哪里开始

从 [startup_recovery.cpp](../../../libs/recovery/src/startup_recovery.cpp) 的范围分析、[startup_runner.cpp](../../../libs/recovery/src/startup_runner.cpp) 的顺序组合、[dispatcher.cpp](../../../libs/recovery/src/dispatcher.cpp) 的验证路由，以及 [manager_startup.cpp](../../../libs/wal/src/manager_startup.cpp) 的尾部处理开始。命令：`rg -n 'LAB-S10\.Q11:.*-BEGIN' libs`。

## 先走通一个小例子

control 表示崩溃恢复且给出合法 redo 起点，WAL 含完整记录、最终截断尾部和一条 loser 页记录。启动先取得经验证可保留前缀，从 redo LSN 按序分发，页 redo 后做事务收尾，成功才转入生产。将 opcode 改未知或破坏中部段，观察任何页面/控制成功状态均不得继续发布。

## 分步实现

1. 分类 control/WAL 状态，验证恢复起点、终点与可接受尾部证明。
2. 用单一物理流按 LSN 读取，先 dispatcher 语义验证再取得页面端口。
3. 组合 heap/Btree redo、持久状态 finalize、缓存排空与同步。
4. 仅在所有步骤成功后提交成功状态；失败保持可重启恢复状态和幂等前缀。

## 必须守住的约束

- 未知 opcode、缺段和中部损坏必须报告，不能降格为 EOF。
- 只允许完整前缀后的截断尾部按 startup manager 契约修复。
- 多次崩溃恢复不回退状态；已写页依靠 LSN 幂等可安全重放。

## 怎样验证

覆盖未知 opcode、缺段/中部损坏、完整前缀截断尾部、反复崩溃恢复后状态不回退。素材：[startup_recovery_test.cpp](../../../libs/recovery/tests/startup_recovery_test.cpp)、[startup_runner_test.cpp](../../../libs/recovery/tests/startup_runner_test.cpp)、[dispatcher_test.cpp](../../../libs/recovery/tests/dispatcher_test.cpp)；独立注册待补齐。
