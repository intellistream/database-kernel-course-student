## 这题要解决什么

查询 `WHERE a=1 ORDER BY b NULLS LAST` 可以利用 `(a,b)` 索引，但只有索引的方向和 NULL 顺序都与请求相符时才可省略 Sort；结果碰巧有序不构成证明。

完成后，你能稳定地比较 SeqScan 与 IndexScan 路径，传播可证明的顺序属性，并让计划形状、结果和访问计数一致。

## 先走通一个小例子

表带 `(a,b)` 索引，查询为 `WHERE a=1 ORDER BY b NULLS LAST`。真实索引 NULL 顺序匹配时才可免 Sort；不匹配时结果相同也必须保留 Sort。

## 分步实现

- 构造 SeqScan 和可用 IndexScan 候选。
- 按等值前缀、选择性和规定的稳定规则比较。
- 从索引前缀推导实际可交付顺序。
- 仅方向与 NULL 顺序均可证明时省略 Sort。

## 必须守住的约束

- 选择必须稳定，不能随机换计划。
- 碰巧有序不是省略 Sort 的证明。
- 测试同时关心计划形状、结果和访问计数。

## 怎样验证

验收必须覆盖：等值前缀优先与稳定择优；不兼容 NULL 次序保留 Sort；结果/实际计划/访问计数。
