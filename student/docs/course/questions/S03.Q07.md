# S03.Q07 唯一索引等待与重查

**验收状态：**本题的 LAB 区间已挖空，但独立测试注册仍待补齐；当前运行 `unit` 的“未执行”不能视为通过。

## 这题要解决什么

并发唯一写入遇到未决冲突时，等待者必须释放树页面并在醒来后重新判断。否则既会阻塞分裂，也可能依据过期结构错误插入。

## 开始前读懂什么

唯一性冲突中的待决 XID、等待前释放所有页 guard、等待后重新下降，以及树在等待期间可能分裂。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-TREE、F-TXN，它们说明验收输入/端口边界，并不意味着仓库中普遍已有同名可直接实例化的类。阅读相关知识只是建立语境，不要求先完成关联题目。

## 先走通一个小例子

两个事务写同一唯一键：先到者未完成时，后到者收集其 XID 并在没有页 guard 的情况下等待。先到者提交则重查后报告冲突；回滚则重查后可能插入，期间树分裂也能重新定位。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 先把冲突探测区分为已决结果和待决 XID 集合。
2. 释放当前路径上全部页 guard，再调用等待端口。
3. 等待返回后从根重新下降并完整检查，而非复用旧叶。
4. 处理多个待决事务、不同完成顺序和重查过程的新分裂。

每完成一步都回到 marker 附近检查调用方期待的是值、错误还是 guard/自有对象；不要把相邻题的策略或事务规则塞进这里。

## 必须守住的约束

绝不能带着页 guard 等待事务；等待后旧定位已失效。必须重做完整唯一检查，不能因先前“无冲突”直接插入；提交与回滚的结果不可混淆。

## 怎样验证

验收必须覆盖以下全部检查：

- 同键竞争不同完成次序
- 等待期间没有页守卫
- 重查遭遇树分裂

现有测试源码可作为场景素材：[btree_unique_test.cpp](../../../libs/access/tests/btree_unique_test.cpp)。它们可能跨题，不能替代本题的独立验收。独立注册待补齐；补齐后可在仓库根目录运行 `python3 labs/run.py unit S03.Q07`，并以实际报告为准。可先运行 `python3 labs/run.py list --stage 03` 核对登记状态。
