# S03.Q07 唯一索引等待与重查

[返回阶段指南](../stages/S03.md)｜[题目总览](../README.md)

## 这题要解决什么

并发唯一写入遇到未决冲突时，等待者必须释放树页面并在醒来后重新判断。否则既会阻塞分裂，也可能依据过期结构错误插入。

## 开始前读懂什么

唯一性冲突中的待决 XID、等待前释放所有页 guard、等待后重新下降，以及树在等待期间可能分裂。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-TREE、F-TXN，用于说明输入和依赖端口。

## 从哪里开始

本题源码入口是 [btree_insert.cpp](../../../libs/access/src/btree_insert.cpp)、[btree_insert.hpp](../../../libs/access/src/btree_insert.hpp)。优先定位 `detail::insert_btree_entry`，这是本题唯一的 LAB 区间；结合 `btree_insert.hpp` 的等待端口和 S03.Q06 的冲突探测结果阅读。实现范围为本题 marker 包围的区间；在仓库根目录检索：

```sh
rg -n 'LAB-S03\.Q07:.*-BEGIN' libs
```

## 先走通一个小例子

两个事务写同一唯一键：先到者未完成时，后到者收集其 XID 并在没有页 guard 的情况下等待。先到者提交则重查后报告冲突；回滚则重查后可能插入，期间树分裂也能重新定位。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 先把冲突探测区分为已决结果和待决 XID 集合。
2. 释放当前路径上全部页 guard，再调用等待端口。
3. 等待返回后从根重新下降并完整检查，而非复用旧叶。
4. 处理多个待决事务、不同完成顺序和重查过程的新分裂。

每步实现后检查调用方的返回类型、错误和对象生命周期。

## 实现约束

绝不能带着页 guard 等待事务；等待后旧定位已失效。必须重做完整唯一检查，不能因先前“无冲突”直接插入；提交与回滚的结果不可混淆。

## 怎样验证

检查以下场景：

- 同键竞争不同完成次序
- 等待期间没有页守卫
- 重查遭遇树分裂

现有测试源码可作为场景素材：[btree_unique_test.cpp](../../../libs/access/tests/btree_unique_test.cpp)。测试范围见对应源码。独立注册待补齐；补齐后可在仓库根目录运行 `python3 labs/run.py unit S03.Q07`，并以实际报告为准。可先运行 `python3 labs/run.py list --stage 03` 核对登记状态。
