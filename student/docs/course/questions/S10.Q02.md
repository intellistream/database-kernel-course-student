# S10.Q02 WAL 分段写入与刷盘

[返回阶段指南](../stages/S10.md)｜[题目总览](../README.md)

## 这题要解决什么

Writer 将环中已发布的 WAL 按页和段边界写到存储，并把 `flush_through` 的成功解释为真正 durable 的 LSN。记录可以跨页、跨段，写入可短写，sync 可失败；保留区间必须覆盖恢复和等待者仍需的字节，关闭时资源也要按顺序释放。

## 开始前读懂什么

阅读 WAL geometry、segment storage 和 writer 的 flush frontier；理解“已写入”与“已同步”不同。环形缓冲提供连续字节，record framing/reader 不属于本题实现前置。

## 从哪里开始

重点文件是 [writer.cpp](../../../libs/wal/src/writer.cpp)、[writer_io.cpp](../../../libs/wal/src/writer_io.cpp)、[segment_storage.cpp](../../../libs/wal/src/segment_storage.cpp)、[segment_directory.cpp](../../../libs/wal/src/segment_directory.cpp) 和 `writer_io.hpp`。运行 `rg -n 'LAB-S10\.Q02:.*-BEGIN' libs`。

## 先走通一个小例子

从一页末尾写入一条跨页且跨段的记录。第一次底层调用只短写一部分，循环应继续直至完整；随后同步成功才让 durable LSN 越过记录末尾。若同步失败，已写前缀可以保留，但调用者不可看到虚假的 durable 前沿，也不能回收这段数据。

## 分步实现

1. 计算页/段切片和段文件定位，处理边界与新段创建。
2. 用短写重试写完连续前缀，准确推进 written frontier。
3. 对 flush target 同步必要段，成功后单调推进 durable frontier。
4. 管理保留、回收和关闭，使在用段及错误后的重试仍有效。

## 实现约束

- 跨页/段记录不能截断或重排。
- 短写和同步失败不能发布错误的 durable LSN。
- 仍被恢复或等待者需要的数据不得回收，资源结束必须可重复处理。

## 怎样验证

覆盖跨页/段记录、短写/同步失败、durable LSN 单调、不能回收仍需数据。现有 [writer_test.cpp](../../../libs/wal/tests/writer_test.cpp) 和 [segment_storage_test.cpp](../../../libs/wal/tests/segment_storage_test.cpp) 是素材；独立注册待补齐。

## 思考题

- 一次 write 返回部分长度后，下一次偏移和剩余长度如何计算？
- durable frontier 为什么只能在哪些 sync 都成功之后前进？

## 延伸阅读

可以把一次 flush 拆成“待写字节区间、已写区间、已同步区间”三栏观察。任何错误返回后，这三栏仍须能解释保留什么以及下一次重试从何处继续，不能只依赖临时文件指针。
