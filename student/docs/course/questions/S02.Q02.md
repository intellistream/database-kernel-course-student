# S02.Q02 类型转换与标量运算规则

[返回阶段指南](../stages/S02.md)｜[题目总览](../README.md)

**验收状态：**本题的 LAB 区间已挖空，但独立测试注册仍待补齐；当前运行 `unit` 的“未执行”不能视为通过。

## 这题要解决什么

同一表达式在不同类型和转换上下文中必须得到一致的含义；这里定义可达的强制转换、运算符选择和数值错误边界。

## 开始前读懂什么

类型的 unknown/NULL 表示、转换上下文的差异，以及标量运算错误与合法 NULL 结果的区别。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-AST，它们说明验收输入/端口边界，并不意味着仓库中普遍已有同名可直接实例化的类。阅读相关知识只是建立语境，不要求先完成关联题目。

## 先走通一个小例子

INT 与 FLOAT 的加法应选择可用的共同运算规则；把浮点值转换为整数时观察规定的舍入。NULL 参与比较得到类型化未知值；除零或越界应返回错误而不是伪造值。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 先列清隐式、赋值与显式上下文允许的边。
2. 搜索转换路径并保留每一步的源/目标类型。
3. 解析一元和二元运算的候选，拒绝无匹配或歧义组合。
4. 实现标量转换与算术边界，最后覆盖 unknown 的定型。

每完成一步都回到 marker 附近检查调用方期待的是值、错误还是 guard/自有对象；不要把相邻题的策略或事务规则塞进这里。

## 必须守住的约束

不能把 NULL 当作普通零值；舍入和溢出检查必须先于窄化写入。非法运算组合必须失败，转换过程不能改变输入值的所有权或污染后续表达式。
