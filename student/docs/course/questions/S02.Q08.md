# S02.Q08 排序与 LIMIT/OFFSET

## 这题要解决什么

ORDER BY 与 LIMIT/OFFSET 的正确性取决于准确的键比较、物化边界和行数解释；这些规则决定哪些行能被观察到以及观察顺序。

## 开始前读懂什么

排序键的多列比较和 NULL 顺序、物化与流式算子的差异，以及 LIMIT/OFFSET 行数表达式的受检求值。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-ROWS，它们说明验收输入/端口边界，并不意味着仓库中普遍已有同名可直接实例化的类。阅读相关知识只是建立语境，不要求先完成关联题目。

## 先走通一个小例子

按两列排序时，第一列相同再比较第二列，NULL 顺序遵从计划约定。LIMIT 0 在 open 后直接 EOF，不应读取子节点；OFFSET 2、LIMIT 1 只输出第三个合格行。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 先编译并计算排序键，区分 NULL 与普通值。
2. 物化子节点结果，排序后以稳定的 next 输出。
3. 在 Limit open 时一次求值行数，检查负数和溢出。
4. 实现 OFFSET 丢弃、LIMIT 截止和 rescan 的重置。

每完成一步都回到 marker 附近检查调用方期待的是值、错误还是 guard/自有对象；不要把相邻题的策略或事务规则塞进这里。

## 必须守住的约束

同键次序应稳定；LIMIT 0 不能为了“预读”而打开/拉取子节点。行数非法必须报错，rescan 不得沿用旧的物化游标或已消耗计数。
