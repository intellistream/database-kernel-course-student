## 这题要解决什么

SQL 前端需要把第三方解析结果转换成项目可长期持有的 Source AST，并精确保留语句边界和拒绝原因，后续绑定才能安全使用它。

## 开始前读懂什么

第三方解析树的生命周期、Source AST 的自有节点，以及 SQL 文本中引号、注释和多语句边界。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-AST，它们说明验收输入/端口边界，并不意味着仓库中普遍已有同名可直接实例化的类。阅读相关知识只是建立语境，不要求先完成关联题目。

## 先走通一个小例子

解析一段含标识符、字符串字面量和两个普通语句的文本，应得到两棵独立 AST；释放第三方解析器对象后，AST 内容仍可访问。未支持的语法应带位置地拒绝。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 先验证文本、UTF-8 与语句边界，避免把引号或注释中的分号当分隔符。
2. 把第三方节点投影为自有的标识符、字面量和普通语句节点。
3. 为 SELECT、VALUES、DML、普通 DDL 分支逐一保留源位置。
4. 在未知节点、超出范围的列表和不支持形态上返回明确错误。

每完成一步都回到 marker 附近检查调用方期待的是值、错误还是 guard/自有对象；不要把相邻题的策略或事务规则塞进这里。

## 必须守住的约束

AST 不得借用第三方树或原始缓冲区的易失内存；多语句边界必须精确。集合、连接和子链接不属于本题，不能被悄悄降级成别的语义。

## 怎样验证

验收必须覆盖以下全部检查：

- 名称与字面量
- 多语句边界
- 错误输入与不支持语法
- 解析器内存释放后 AST 有效
