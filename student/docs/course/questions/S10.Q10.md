# S10.Q10 事务与目录恢复收尾

[返回阶段指南](../stages/S10.md)｜[题目总览](../README.md)

验收状态：本题的独立测试登记尚待补齐；现有测试只作素材，夹具名只表示契约。

## 这题要解决什么

页 redo 后仍要恢复非页面持久状态：提交/中止记录定案 CLOG，未完成或遗弃 XID 设为中止，next XID/OID 不得回退，并协调目录前沿和物理索引身份。恢复中再次失败时，已经安全持久的部分可重试，不能把 winner/loser 或目录一致性伪造出来。

## 开始前读懂什么

阅读 `DurableStateReplayer` 的 seed/result/finalize、CLOG 的 recovery-resolved frontier、catalog recovery port 和 catalog-index 校验接口。物理页 redo 在 S10.Q09；本题对它的普通 XID 只收集前沿，不重新应用页面。

## 从哪里开始

先读 [durable_state_redo.cpp](../../../libs/recovery/src/durable_state_redo.cpp) 的 replay/finalize，再看 [catalog_recovery.cpp](../../../libs/recovery/src/catalog_recovery.cpp) 的 OID 协调和 [catalog_index.cpp](../../../libs/recovery/src/catalog_index.cpp) 的身份验证。命令：`rg -n 'LAB-S10\.Q10:.*-BEGIN' libs`。

## 先走通一个小例子

流中有 T1 的提交记录、T2 的页面记录但无完成记录，以及 checkpoint 声明的 next XID/OID。重放后 T1 为 committed，finalize 将 T2 中止，并把分配前沿至少推进过两者与 checkpoint。若 catalog 前沿发布失败，已刷新的 CLOG 定案不能回退；重试继续协调。目录索引身份不匹配时必须报告。

## 分步实现

1. 按单调物理 LSN 接受完成与 checkpoint 记录，拒绝冲突终态。
2. 汇总 seed、完成记录、已验证物理 XID 和已开 CLOG 前沿得到 next XID。
3. finalize 未定案 XID、刷写 CLOG 并推进 recovery-resolved frontier。
4. 在 CLOG 成功后协调 OID 前沿与目录/索引身份，保留失败后的重试语义。

## 必须守住的约束

- winner/loser 必须定案；未完成不等于可提交。
- 下一 ID 单调不回退，即使控制映像较旧或恢复中再次失败。
- 目录与物理索引不一致必须结构化报告，不能臆造 catalog WAL 载荷。

## 怎样验证

覆盖 winner/loser、下一 ID 不回退、恢复中再次失败、目录和物理索引不一致报告。现有 [durable_state_redo_test.cpp](../../../libs/recovery/tests/durable_state_redo_test.cpp)、[catalog_recovery_test.cpp](../../../libs/recovery/tests/catalog_recovery_test.cpp)、[catalog_index_test.cpp](../../../libs/recovery/tests/catalog_index_test.cpp) 是素材；独立注册待补齐。

## 卡住时先想这几个问题

- 为什么页面记录中的普通 XID 也必须推进恢复分配前沿？
- catalog 失败后，哪些 CLOG 修改已可靠，重试又应从哪里继续？

## 延伸阅读

finalize 的幂等性应建立在已经持久化的 CLOG 状态和单调前沿上，而不是假设首次调用完整成功。这样即使目录协调落后，也能在不重新解释胜者和失败者的前提下安全重试。
