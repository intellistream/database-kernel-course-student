# S03.Q01 索引键与节点页算法

## 这题要解决什么

B+Tree 的每次定位和分裂都依赖正确的键顺序与节点页格式。本题建立复合键、RID 次序和页内条目的可验证表示。

## 开始前读懂什么

复合键的编码与比较、键相等时 RID 的次序、叶页和内部页槽位格式，以及重组不改变逻辑条目。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-TREE，用于说明输入和依赖端口。

## 从哪里开始

本题源码入口是 [btree_key.cpp](../../../libs/access/src/btree_key.cpp)、[btree_key_internal.hpp](../../../libs/access/src/btree_key_internal.hpp)、[btree_page.cpp](../../../libs/access/src/btree_page.cpp)、[btree_page_read_view.hpp](../../../libs/access/src/btree_page_read_view.hpp)。优先定位 `BtreeKeyLayout::create`、`encode`、`compare`、`compare_prefix`，以及 `BtreePage::append_leaf_entry`、`insert_leaf_entry`、`insert_separator_and_child`。实现范围为本题 marker 包围的区间；在仓库根目录检索：

## 先走通一个小例子

两条复合键前缀相同而 RID 不同时，排序应有确定次序；含 NULL 或 FLOAT 的键要按格式契约编码。页接近容量时插入或重组后，所有条目仍可读且槽位不重叠。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 先验证键布局、组件类型和规范编码长度。
2. 实现全键与前缀比较，明确 RID 作为叶条目平局裁决。
3. 填充叶/内部节点的有序槽位并检查容量。
4. 重组页内容后重建 header、opaque 与可读槽位。

每步实现后检查调用方的返回类型、错误和对象生命周期。

## 实现约束

浮点与 NULL 必须按既定格式比较，不能依赖裸字节的偶然顺序。槽位区和负载区不能相交；重组不能丢条目或改变重复键/RID 的相对语义。

## 怎样验证

检查以下场景：

- 重复键/RID 次序
- NULL/FLOAT 格式契约
- 节点容量与重组边界

现有测试源码可作为场景素材：[btree_key_test.cpp](../../../libs/access/tests/btree_key_test.cpp)、[btree_page_test.cpp](../../../libs/access/tests/btree_page_test.cpp)。测试范围见对应源码。独立注册待补齐；补齐后可在仓库根目录运行 `python3 labs/run.py unit S03.Q01`，并以实际报告为准。可先运行 `python3 labs/run.py list --stage 03` 核对登记状态。
