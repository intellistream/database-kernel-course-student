# S08.Q03 CLOG 状态与持久化

[返回阶段指南](../stages/S08.md)｜[题目总览](../README.md)

验收状态：本题的独立测试登记尚待补齐；现有测试只作素材，F-IO、F-TXN 是夹具契约名。

## 这题要解决什么

CLOG 将每个 XID 的进行中、提交和中止状态保存为可重开读取的段页。事务可见性和崩溃恢复都依赖它，因此题目不仅要改内存缓存，还要处理段扩展、脏队列、写入和同步失败，使已报告的持久化状态真实存在。

## 开始前读懂什么

先读 `CommitLog` 的状态枚举、段定位和给定二进制格式；理解缓存快照与磁盘段的关系；区分“设置状态”与“flush 已捕获目标”。格式字段已给定，阅读它不等于需要别题实现。

## 从哪里开始

主入口在 [commit_log.cpp](../../../libs/transaction/src/commit_log.cpp) 的 `open`、`set_status`、`status`、`flush`；段内寻址和发布在 [commit_log_segment.cpp](../../../libs/transaction/src/commit_log_segment.cpp)，文件发现位于 [commit_log_files.cpp](../../../libs/transaction/src/commit_log_files.cpp)。执行 `rg -n 'LAB-S08\.Q03:.*-BEGIN' libs` 只定位本题 marker。

## 先走通一个小例子

让一个 XID 恰好落在段尾，另一个落在下一段。先把前者标为提交、后者标为中止并 flush，关闭后重开应读回相同状态。若第二个段同步失败，观察 dirty 状态仍可重试，不能把未落盘的映像当成持久化版本。

## 分步实现

1. 实现段名解析、XID 到状态位置的定位及非法编码检测。
2. 建立按需安装/查找段和缓存读写，拒绝非法状态迁移。
3. 用脏队列捕获 flush 目标，分别写段与元数据。
4. 在重开、跨段和失败重试路径中恢复一致的缓存与持久化视图。

## 必须守住的约束

- 跨段边界、损坏格式与 I/O 错误都不能静默降级。
- 状态发布和“已持久化”标记必须在成功写入与同步后发生。
- 恢复收尾只能按契约把遗留 in-progress 定案，不能伪造提交。

## 怎样验证

完整覆盖跨段边界、非法状态迁移、写入/同步失败、重开后的状态与损坏检测。以 [commit_log_test.cpp](../../../libs/transaction/tests/commit_log_test.cpp) 和 [commit_log_segment_test.cpp](../../../libs/transaction/tests/commit_log_segment_test.cpp) 为素材；本题独立验收注册仍待补齐。

## 卡住时先想这几个问题

- 一个段刚扩展但元数据尚未同步时，重开能安全相信什么？
- 脏队列中失败的段怎样保持可重试而不重复宣称完成？
