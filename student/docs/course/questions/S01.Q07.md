## 这题要解决什么

堆页既要容纳变长记录，也要让 RID 在插入、删除和整理后仍指向正确的逻辑记录。这里负责页内空间与槽位的基本秩序。

## 开始前读懂什么

堆页头、line pointer 与 RID 的关系，记录字节区和槽位区的相向增长，以及整理时保持逻辑身份。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-HEAP，用于说明输入和依赖端口。

## 从哪里开始

本题源码入口是 [heap_page.cpp](../../../libs/access/src/heap_page.cpp)、[heap_prune.cpp](../../../libs/access/src/heap_prune.cpp)。优先定位 `HeapPage::insert_tuple`、`insert_tuple_at`、`find_unused_slot`、`repair_fragmentation`，以及 `CompactionOperation::plan_layout`、`run` 的整理边界。实现范围为本题 marker 包围的区间；在仓库根目录检索：

```sh
rg -n 'LAB-S01\.Q07:.*-BEGIN' libs
```

## 先走通一个小例子

插入两条长短不同记录，删除或标记一个槽位后再插入；可复用槽位应得到合理处理。整理后，仍存活记录通过原 RID 读取的内容应不变。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 先验证页头、槽位形状和记录范围，建立可复用槽位的判定。
2. 实现新槽与复用槽的插入，按实际字节数检查连续空间。
3. 连续空间不足而总空闲足够时规划整理，并在写入前固定布局。
4. 整理后重写偏移和页头，复查记录范围互不重叠。

每步实现后检查调用方的返回类型、错误和对象生命周期。

## 实现约束

RID 的槽位身份不能因整理改变；记录区与槽位区不能相交。任何验证失败不得写半个布局，标记死亡、重定向和未用状态要彼此可区分。

## 怎样验证

检查以下场景：

- 满页与槽位复用
- 长短记录
- 整理后 RID 与存活记录不变

现有测试源码可作为场景素材：[heap_page_test.cpp](../../../libs/access/tests/heap_page_test.cpp)、[heap_maintenance_test.cpp](../../../libs/access/tests/heap_maintenance_test.cpp)。测试范围见对应源码。独立注册待补齐；补齐后可在仓库根目录运行 `python3 labs/run.py unit S01.Q07`，并以实际报告为准。可先运行 `python3 labs/run.py list --stage 01` 核对登记状态。
