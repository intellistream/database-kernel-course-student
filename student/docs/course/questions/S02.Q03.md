# S02.Q03 名称与作用域绑定

[返回阶段指南](../stages/S02.md)｜[题目总览](../README.md)

**独立测试：**待配置。

## 这题要解决什么

SQL 中同名列、别名和嵌套范围很容易产生误解。绑定器需要给每个名称一个唯一、稳定且自有的来源描述。

## 开始前读懂什么

FROM 范围、投影别名范围、限定名和非限定名查找，以及绑定结果对目录快照的所有权。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-AST、F-CATALOG，用于说明输入和依赖端口。

## 从哪里开始

本题源码入口是 [binder.cpp](../../../libs/sql/src/binder.cpp)、[binder_scope.cpp](../../../libs/sql/src/binder_scope.cpp)、[binder_scope_internal.hpp](../../../libs/sql/src/binder_scope_internal.hpp)。优先定位 `bind_from`、`bind_named_table`、`bind_column_reference`、`bind_qualified_column_reference`、`expand_wildcard`，并追踪 Scope 的 `lookup_unqualified_from`。实现范围为本题 marker 包围的区间；在仓库根目录检索：

```sh
rg -n 'LAB-S02\.Q03:.*-BEGIN' libs
```

## 先走通一个小例子

两张表都含 id 时，裸 id 必须报歧义，a.id 可绑定到 a。`a.*` 的列顺序应稳定；内层别名遮蔽外层同名时，应按相应层级选择。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 先把目录表与别名登记为 scope entry，并保存自有列描述。
2. 分别实现限定名、非限定名和 DML 目标列查找。
3. 在投影阶段登记别名，再按允许的位置解析它。
4. 展开星号时按 FROM 的既定次序收集列并保留来源。

每步实现后检查调用方的返回类型、错误和对象生命周期。

## 实现约束

歧义不能凭任意顺序消解；限定名不能越过错误的遮蔽层。绑定产物不得借用可变目录视图，星号展开的顺序必须稳定。

## 怎样验证

检查以下场景：

- 同名列歧义
- 遮蔽与限定名
- 星号次序
- 绑定结果不借用目录视图

现有测试源码可作为场景素材：[binder_test.cpp](../../../libs/sql/tests/binder_test.cpp)。测试范围见对应源码。独立注册待补齐；补齐后可在仓库根目录运行 `python3 labs/run.py unit S02.Q03`，并以实际报告为准。可先运行 `python3 labs/run.py list --stage 02` 核对登记状态。
