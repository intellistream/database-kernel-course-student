# S10.Q06 业务变更的 WAL 生成

[返回阶段指南](../stages/S10.md)｜[题目总览](../README.md)

验收状态：本题的独立测试登记尚待补齐；现有测试只作素材，夹具名只表示契约。

## 这题要解决什么

堆、B+Tree、事务和目录操作只有把足够的记录种类、payload、FPI 与页面 LSN 串起来，崩溃后才可重放。本题生成这些业务变更的 WAL，并规定 append 成功前页面不能对外发布新状态。不要把日志生成与后续物理 redo 或事务恢复收尾混在一起。

## 开始前读懂什么

阅读 Heap/Btree/transaction WAL 的记录类型、block 角色和给定 payload codec；理解 write-ahead 原则、页面结束 LSN 和批量多页记录。FPI/压缩选择来自 S10.Q05，字段格式并非要重新设计。

## 先走通一个小例子

一次 heap update 影响旧、新版本页；先构造带正确页面角色和变更字节的记录，append 返回结束 LSN 后才把两个候选页写入该 LSN 并发布。把 append 强制失败，观察旧页仍完整可见。对 Btree split 再试跨页记录，记录顺序与每块 LSN 必须可被 redo 解释。

## 分步实现

1. 为各变更家族确定记录类型、必需字段和 block 顺序。
2. 构造 payload、FPI/delta 与 LSN 对齐，验证大小和角色。
3. 调用 manager append，并在成功后才提交候选页/目录/事务状态。
4. 覆盖批量和跨页变更，确保失败不泄露半个逻辑操作。

## 实现约束

- 每种变更记录必须含恢复所需字段，不能依赖运行时隐藏状态。
- append 失败不发布页面新状态；页面 LSN 与记录末尾严格对应。
- 多页与批量记录保持可按 WAL 顺序重放，FPI 决策使用本题给定契约。

## 怎样验证

覆盖每种变更记录字段、append 失败不发布新页、LSN 对齐、批量与跨页记录。现有 [heap_wal_test.cpp](../../../libs/recovery/tests/heap_wal_test.cpp)、[btree_wal_test.cpp](../../../libs/recovery/tests/btree_wal_test.cpp)、[transaction_wal_test.cpp](../../../libs/recovery/tests/transaction_wal_test.cpp)、[catalog_recovery_test.cpp](../../../libs/recovery/tests/catalog_recovery_test.cpp) 是素材；独立注册待补齐。

## 思考题

- 若崩溃发生在 append 返回前，恢复能否安全看见候选页变化？
- 一条跨页记录为何需要让每个块都有清楚的角色与结束 LSN？

## 延伸阅读

把页面候选、WAL record 和最终 page LSN 视为一个发布单元会更容易审查。无论记录由堆、树还是事务生成，先失败的 append 都必须让该单元完全不对外出现。
