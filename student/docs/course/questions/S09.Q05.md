# S09.Q05 SSI 读集与谓词锁

[返回阶段指南](../stages/S09.md)｜[题目总览](../README.md)

验收状态：本题的独立测试登记尚待补齐；现有测试只作素材，夹具名只表示契约。

## 这题要解决什么

Serializable 隔离不能只记住读到的元组：一次空范围扫描也说明事务依赖“这里没有匹配项”。本题为点、范围和全表读取登记谓词锁，收集读写事件，并在读集变大时按规则提升锁粒度。事务结束时要保留仍被冲突裁决需要的事实，再安全回收。

## 开始前读懂什么

阅读 SSI target/range 的表示、predicate lock 的层级和 read set 生命周期；区分“读事件”与“检测到冲突”。冲突图和提交裁决是 S09.Q06，本题只提供完整、可匹配的事实。

## 从哪里开始

从 [ssi_predicate_locks.cpp](../../../libs/transaction/src/ssi_predicate_locks.cpp)、[ssi_read_locks.cpp](../../../libs/transaction/src/ssi_read_locks.cpp)、[ssi_lifecycle.cpp](../../../libs/transaction/src/ssi_lifecycle.cpp) 入手；扫描和写入接入位于 [heap_scan.cpp](../../../libs/access/src/heap_scan.cpp)、[heap_fetch.cpp](../../../libs/access/src/heap_fetch.cpp)、[logical_scan_ssi.cpp](../../../libs/engine/src/logical_scan_ssi.cpp)、[physical_modify_port.cpp](../../../libs/engine/src/physical_modify_port.cpp)。命令：`rg -n 'LAB-S09\.Q05:.*-BEGIN' libs`。

## 先走通一个小例子

T1 扫描键范围 [10,20] 得到空集，也必须登记该范围。T2 随后插入 15，写事件应匹配 T1 的谓词读。让 T1 重复读取许多点，观察点锁按既定阈值提升为范围或表锁；T1 结束时其读集不能早于必要冲突信息消失。

## 分步实现

1. 表达点、范围、全表目标，并实现读/写匹配。
2. 在 fetch、scan 与逻辑扫描入口收集读，即使结果为空。
3. 根据给定规则提升锁粒度，去重但不丢覆盖范围。
4. 将读写事件与事务生命周期衔接，按安全时机保留和回收。

## 实现约束

- 空扫描也是谓词读；点/范围/全表的包含关系不能漏匹配。
- 锁提升不能扩大成错误目标或缩小已承诺保护范围。
- 事务结束后只回收不再被 SSI 裁决引用的读集。

## 怎样验证

覆盖点/范围/全表读、扫描空结果仍有谓词读、锁提升、事务结束后的保留/回收。现有 [ssi_predicate_locks_test.cpp](../../../libs/transaction/tests/ssi_predicate_locks_test.cpp)、[ssi_read_locks_test.cpp](../../../libs/transaction/tests/ssi_read_locks_test.cpp)、[ssi_lifecycle_test.cpp](../../../libs/transaction/tests/ssi_lifecycle_test.cpp) 是素材；独立注册待补齐。

## 思考题

- 没有返回元组的范围查询究竟依赖了数据库的哪项事实？
- 把多个点锁提升后，怎样证明未来写入仍会匹配原来的每个点？

## 延伸阅读

读集的价值在于让之后的写入仍能找到先前观察到的范围。因此调试时应同时打印被读目标和被写目标的归一化形式，确认空扫描与非空扫描经过同一套匹配规则。
