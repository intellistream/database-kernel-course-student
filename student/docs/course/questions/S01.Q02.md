# S01.Q02 CLOCK 替换

## 这题要解决什么

缓冲池空间耗尽时，需要用访问热度挑选可回收帧，同时不碰仍被使用或正在 I/O 的帧。CLOCK 用低成本的二次机会近似近期访问。

## 开始前读懂什么

Frame 的 pin 与 I/O 状态、替换器只提出带 guard 的候选，以及 CLOCK 的“引用提示不是固定计数”。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-FRAME，用于说明输入和依赖端口。

## 从哪里开始

本题源码入口是 [replacement.cpp](../../../libs/storage/src/replacement.cpp)。优先定位 `ClockReplacer::evict`、`on_pin`、`on_remove` 和 `Impl::decrement_if_positive`，理解候选声明与访问提示如何分离。实现范围为本题 marker 包围的区间；在仓库根目录检索：

```sh
rg -n 'LAB-S01\.Q02:.*-BEGIN' libs
```

## 先走通一个小例子

三个可替换帧中，刚访问过的帧先获得一次机会；另一个未引用帧可成为候选。把全部帧固定后应返回不可用，解除一个固定后再次调用应能恢复。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 读清 Frame::try_claim_evictable 返回 guard 的意义，再保存私有使用计数和时钟位置。
2. 在 on_pin 中只更新访问提示，不代替 BufferPool 改变 pin 数。
3. 扫描时先消耗正提示，再对零提示帧尝试声明；声明竞争失败就继续。
4. 处理 remove 与候选耗尽，使后续恢复通知仍能重新参与选择。

每步实现后检查调用方的返回类型、错误和对象生命周期。

## 实现约束

不能驱逐固定或 I/O 中的帧；返回的是受害 guard 声明，不是裸 FrameId。使用计数要有上界，扫描也必须有界；竞争导致的候选失效不能破坏时钟位置。

## 怎样验证

检查以下场景：

- 有引用帧得到二次机会
- 固定帧不可驱逐
- 全固定后可恢复

现有测试源码可作为场景素材：[replacement_test.cpp](../../../libs/storage/tests/replacement_test.cpp)。测试范围见对应源码。独立注册待补齐；补齐后可在仓库根目录运行 `python3 labs/run.py unit S01.Q02`，并以实际报告为准。可先运行 `python3 labs/run.py list --stage 01` 核对登记状态。
