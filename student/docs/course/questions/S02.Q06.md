## 这题要解决什么

执行器需要把绑定表达式编译为可在不同行和参数上反复运行的程序，同时忠实实现 SQL 的 UNKNOWN 语义与错误隔离。

## 开始前读懂什么

表达式程序的编译与执行上下文、SQL 三值逻辑，以及类型化 NULL 与错误传播。子计划调用不在范围内。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-AST、F-ROWS，用于说明输入和依赖端口。

## 先走通一个小例子

对 TRUE、FALSE、NULL 组合测试 AND/OR/NOT，观察 UNKNOWN 的传播；同一程序用新参数重绑定后应基于新值求值。一次除零失败后，下一行正常输入仍能独立计算。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 先编译字面量、输入和参数加载，建立 descriptor 绑定。
2. 加入算术、比较、cast 与 NULL 感知的结果表示。
3. 按三值真值表处理布尔、IN、BETWEEN、IS NULL。
4. 让每次求值的临时状态独立，并把错误准确返回给调用者。

每步实现后检查调用方的返回类型、错误和对象生命周期。

## 实现约束

UNKNOWN 不是 C++ 的 false；NULL 必须携带类型。重绑定不能遗留旧参数或输入引用，单次失败不能污染下次执行的栈、寄存器或输出。

## 怎样验证

检查以下场景：

- TRUE/FALSE/UNKNOWN 真值表
- 类型化 NULL
- 重绑定
- 求值失败不污染后续输入

现有测试源码可作为场景素材：[expression_test.cpp](../../../libs/execution/tests/expression_test.cpp)、[exec_context_test.cpp](../../../libs/execution/tests/exec_context_test.cpp)。测试范围见对应源码。独立注册待补齐；补齐后可在仓库根目录运行 `python3 labs/run.py unit S02.Q06`，并以实际报告为准。可先运行 `python3 labs/run.py list --stage 02` 核对登记状态。
