## 这题要解决什么

执行器需要把绑定表达式编译为可在不同行和参数上反复运行的程序，同时忠实实现 SQL 的 UNKNOWN 语义与错误隔离。

## 开始前读懂什么

表达式程序的编译与执行上下文、SQL 三值逻辑，以及类型化 NULL 与错误传播。子计划调用不在范围内。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-AST、F-ROWS，它们说明验收输入/端口边界，并不意味着仓库中普遍已有同名可直接实例化的类。阅读相关知识只是建立语境，不要求先完成关联题目。

## 先走通一个小例子

对 TRUE、FALSE、NULL 组合测试 AND/OR/NOT，观察 UNKNOWN 的传播；同一程序用新参数重绑定后应基于新值求值。一次除零失败后，下一行正常输入仍能独立计算。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 先编译字面量、输入和参数加载，建立 descriptor 绑定。
2. 加入算术、比较、cast 与 NULL 感知的结果表示。
3. 按三值真值表处理布尔、IN、BETWEEN、IS NULL。
4. 让每次求值的临时状态独立，并把错误准确返回给调用者。

每完成一步都回到 marker 附近检查调用方期待的是值、错误还是 guard/自有对象；不要把相邻题的策略或事务规则塞进这里。

## 必须守住的约束

UNKNOWN 不是 C++ 的 false；NULL 必须携带类型。重绑定不能遗留旧参数或输入引用，单次失败不能污染下次执行的栈、寄存器或输出。

## 怎样验证

验收必须覆盖以下全部检查：

- TRUE/FALSE/UNKNOWN 真值表
- 类型化 NULL
- 重绑定
- 求值失败不污染后续输入
