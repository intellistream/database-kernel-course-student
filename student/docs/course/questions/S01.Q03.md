# S01.Q03 LRU 替换

[返回阶段指南](../stages/S01.md)｜[题目总览](../README.md)

**验收状态：**本题的 LAB 区间已挖空，但独立测试注册仍待补齐；当前运行 `unit` 的“未执行”不能视为通过。

## 这题要解决什么

缓冲池需要在各个既定分桶内保留最近使用次序，才能从恰当的 LRU 端挑选可替换帧。这题维护的是分桶策略的私有拓扑。

## 开始前读懂什么

侵入式桶内链表、MRU/LRU 次序，以及替换声明失败后的 restore 协作。此题的分桶 LRU 不是全局 LRU。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-FRAME，它们说明验收输入/端口边界，并不意味着仓库中普遍已有同名可直接实例化的类。阅读相关知识只是建立语境，不要求先完成关联题目。

## 从哪里开始

本题源码入口是 [replacement.cpp](../../../libs/storage/src/replacement.cpp)。优先定位 `LruBucket::contains`、`unlink`、`push_front`，再看 `LruReplacer::evict`、`on_pin`、`on_remove` 如何驱动桶内次序。这些文件也含别题区域，只能编辑本题 marker 包围的区间；在仓库根目录检索：

```sh
rg -n 'LAB-S01\.Q03:.*-BEGIN' libs
```

## 先走通一个小例子

同一桶内依次访问 A、B、再访问 A，B 应先成为该桶的候选；固定 B 后不得选它。一次替换回写失败并 restore 后，它还应重新参与原桶的次序。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 先维护桶内节点的存在性、前后链接和头尾边界。
2. 把重复访问变成“摘下再放到本桶 MRU 端”，而不是制造重复节点。
3. 从轮到的桶的 LRU 端取候选，并用 Frame 声明确认可替换。
4. 在 remove 和恢复路径收回或重新接回节点，检查多个桶之间不串链。

每完成一步都回到 marker 附近检查调用方期待的是值、错误还是 guard/自有对象；不要把相邻题的策略或事务规则塞进这里。

## 必须守住的约束

每帧至多在一个桶的一条链上；桶边界不能被全局次序覆盖。固定帧和声明失败的帧都不可作为结果；恢复必须保留策略状态的一致性。

## 怎样验证

验收必须覆盖以下全部检查：

- 更新访问次序
- 桶边界与固定帧
- 失败后候选可恢复

现有测试源码可作为场景素材：[replacement_test.cpp](../../../libs/storage/tests/replacement_test.cpp)。它们可能跨题，不能替代本题的独立验收。独立注册待补齐；补齐后可在仓库根目录运行 `python3 labs/run.py unit S01.Q03`，并以实际报告为准。可先运行 `python3 labs/run.py list --stage 01` 核对登记状态。
