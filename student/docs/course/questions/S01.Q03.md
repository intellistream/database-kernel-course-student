# S01.Q03 LRU 替换

[返回阶段指南](../stages/S01.md)｜[题目总览](../README.md)

## 这题要解决什么

缓冲池需要在各个既定分桶内保留最近使用次序，才能从恰当的 LRU 端挑选可替换帧。这题维护的是分桶策略的私有拓扑。

## 开始前读懂什么

侵入式桶内链表、MRU/LRU 次序，以及替换声明失败后的 restore 协作。此题的分桶 LRU 不是全局 LRU。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-FRAME，用于说明输入和依赖端口。

## 从哪里开始

本题源码入口是 [replacement.cpp](../../../libs/storage/src/replacement.cpp)。优先定位 `LruBucket::contains`、`unlink`、`push_front`，再看 `LruReplacer::evict`、`on_pin`、`on_remove` 如何驱动桶内次序。实现范围为本题 marker 包围的区间；在仓库根目录检索：

```sh
rg -n 'LAB-S01\.Q03:.*-BEGIN' libs
```

## 先走通一个小例子

同一桶内依次访问 A、B、再访问 A，B 应先成为该桶的候选；固定 B 后不得选它。一次替换回写失败并 restore 后，它还应重新参与原桶的次序。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 先维护桶内节点的存在性、前后链接和头尾边界。
2. 把重复访问变成“摘下再放到本桶 MRU 端”，而不是制造重复节点。
3. 从轮到的桶的 LRU 端取候选，并用 Frame 声明确认可替换。
4. 在 remove 和恢复路径收回或重新接回节点，检查多个桶之间不串链。

每步实现后检查调用方的返回类型、错误和对象生命周期。

## 实现约束

每帧至多在一个桶的一条链上；桶边界不能被全局次序覆盖。固定帧和声明失败的帧都不可作为结果；恢复必须保留策略状态的一致性。

## 怎样验证

检查以下场景：

- 更新访问次序
- 桶边界与固定帧
- 失败后候选可恢复

现有测试源码可作为场景素材：[replacement_test.cpp](../../../libs/storage/tests/replacement_test.cpp)。测试范围见对应源码。独立注册待补齐；补齐后可在仓库根目录运行 `python3 labs/run.py unit S01.Q03`，并以实际报告为准。可先运行 `python3 labs/run.py list --stage 01` 核对登记状态。
