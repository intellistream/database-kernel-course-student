# S03.Q06 唯一性与存量冲突检测

[返回阶段指南](../stages/S03.md)｜[题目总览](../README.md)

**验收状态：**本题的 LAB 区间已挖空，但独立测试注册仍待补齐；当前运行 `unit` 的“未执行”不能视为通过。

## 这题要解决什么

唯一约束的判断不能只看当前页或裸键值；它需要跨叶检查完整复合键，并按既定版本事实和 NULL 规则作出结论。

## 开始前读懂什么

唯一索引的全复合键相等、NULL 可重复规则、跨叶相等键探测，以及给定版本事实的消费方式。本题使用的夹具契约见[夹具说明](../fixtures.md)：F-TREE、F-TXN，它们说明验收输入/端口边界，并不意味着仓库中普遍已有同名可直接实例化的类。阅读相关知识只是建立语境，不要求先完成关联题目。

## 先走通一个小例子

存量中有相同非 NULL 复合键时插入/批建应冲突；相等键跨叶仍要被发现。任一键分量为 NULL 的两行可同时存在；已提交和已中止版本按端口提供事实得到不同结果。

先在纸上标出输入、应返回的状态和需要保留的资源；这比一开始扩展到完整工作负载更容易发现边界错位。

## 分步实现

1. 先区分全键相等、RID 相等和“含任一 NULL”的可重复情形。
2. 从定位叶探测相等键范围，并检查相邻叶边界。
3. 对批量条目按排序邻接关系做重复检测。
4. 消费版本端口给出的状态，返回冲突、可插入或待处理结论。

每完成一步都回到 marker 附近检查调用方期待的是值、错误还是 guard/自有对象；不要把相邻题的策略或事务规则塞进这里。

## 必须守住的约束

必须比较完整复合键；跨叶边界不能漏查。NULL 规则不能用普通相等替代，事务可见性/裁决不是本题自行推导的算法。

## 怎样验证

验收必须覆盖以下全部检查：

- 存量重复
- 跨叶版本
- 复合 NULL
- 已提交/已中止版本的不同裁决

现有测试源码可作为场景素材：[btree_unique_test.cpp](../../../libs/access/tests/btree_unique_test.cpp)、[btree_bulk_build_test.cpp](../../../libs/access/tests/btree_bulk_build_test.cpp)。它们可能跨题，不能替代本题的独立验收。独立注册待补齐；补齐后可在仓库根目录运行 `python3 labs/run.py unit S03.Q06`，并以实际报告为准。可先运行 `python3 labs/run.py list --stage 03` 核对登记状态。
